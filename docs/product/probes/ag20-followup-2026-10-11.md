# AG20 真实试用失败分析、修复与有限复验

2026-10-11。用户授权：分析三公司未产出合格研究的原因，修复后进行一次有限试用，继续临时复用现有供应商和模型。工程修复与研究质量验收分别记录。**本轮仍无合格研究答案或正式公司观点，不能宣称问题全部解决。**

## 原因与证据

1. **证券身份没有接通。** 旧试用传入内部 listing/case 引用，快照工具却要求完整 ticker。招商银行和国电南瑞的私有拒绝草稿明确说明缺少 listing→ticker 映射，因而未取数；海康威视的未提交进展也只有内部 ID。前次已经修复服务端 `target_identities`，本轮确认模型能够识别公司；不能把前次全部失败归因于模型能力。
2. **接口 schema 比实际允许范围宽。** `entity_ref.ref` 原来是任意 `ObjectRef`，实际渲染只支持 listing。首轮复验中，模型按“数字身份使用 entity_ref”的提示，把 case/method/task/message 也放进该节点，随后被主体检查拒绝。这是模型接口与执行约束不一致。现已在 JSON schema 和 Pydantic 解析器中限定精确 listing；原有 listing 序列化和指纹不变。外部证券仍被授权检查拒绝。
3. **可纠正错误直接结束任务。** 原试用 `agent_retries=0`；业务文本/证据引用校验也在 native run 之外完成，无法进入框架纠错。现在对有限的格式/引用错误提供安全字段反馈，模型可在同 Task 内纠正。每次纠正继续经过持久预算、权限和取消检查；越权、租约、配置变化等不转成模型重试。错误上限耗尽仍停止，私有拒绝草稿、真实 usage 和安全公开错误继续保留。
4. **初始计划被当作最终输出。** 首轮国电南瑞返回了七维计划和缺口，但没有执行任何取证；Task 的 partial 不是合格研究。指令现在明确要求真正调用保存及查询工具；对没有已有证据、没有提交进展、也无明确停止原因的公司研究终稿提供继续取证反馈。诚实说明不能继续的 partial 仍允许保存，不伪造事实或强制发表方向结论。
5. **多轮上下文与预算预留成本过高。** 当前输入预留按字节保守计数，不能当作供应商实测 token。成功请求中，预留约 4.5–8.8 万，实际输入加输出约 1.3–2.7 万；预算账本并未把预留全部算作实际消费。工具 schema、历史输出和工具回执会随轮次增加，下一次请求仍可能在实际额度尚有余额时被拒绝。发现 `save_research_progress` 重复回传完整计划和渲染正文后，已改为模型端短回执（状态、产物引用、证据引用），数据库原始内容保持完整。**该回执优化在付费复验结束后完成，只经离线验证，不能声称真实多轮预算阻塞已经消失。** 未使用未经验证的 tokenizer 换算或经验比例放松预留。

- 短回执及既有组合、研究、执行器重点 73 passed；新增回执验证确认数据库保存完整正文和局限，模型端不重复回传。其首次断言遗漏渲染器追加的局限文本，已修正为验证正文前缀和完整结构。
- 第一轮全量在补充修复时中断（1772 passed / 1 failed / 3 skipped）；失败为硬编码上午观察时点已经早于实际发布时点，测试改用发布之后的次日上午。第二轮全量 2200 passed / 1 failed / 3 skipped，失败为组合 fixture 的上下文预留越界；短回执修复后原用例通过，未提高该 fixture 的预算。一次刚开始的全量因新增断言修正而主动中断，不计通过。

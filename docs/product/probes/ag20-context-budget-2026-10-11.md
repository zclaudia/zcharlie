## 已修复的机制

- **按实际发送内容预留。** 真实模型在 HTTP 发送前按实际请求体 UTF-8 字节数保守估算输入，加有限输出额度；不再计算框架 `repr`，也没有引入猜测的 token/字节折算。成功、失败、未知用量仍走持久账本；发送前仍检查权限、取消和配置。记录 messages/tools/response-format 大小以及未获准发送的预估值，不记录请求正文或凭据。注入测试模型没有 HTTP，以结构化 JSON 估算。
- **去掉无关、重复内容。** 公司研究不再反复携带组合方案与用户控制的输出 schema，约 18622→9928 字节；完整运行时契约和权限检查保留。工具 schema 去掉冗余展示标题；进展工具只返回短回执，数据库正文完整。已知字段的 `capture_snapshot` 一次返回保存引用和原始材料，减少“读→存→再读”。字段名在原生参数校验层检查，错误不再直接终止整个任务。
- **压缩旧交互。** 仅投影已完整结束的旧调用，保留成功调用的参数与完整工具结果；旧推理与已拒绝草稿不作为证据反复重放。拒绝保留字段反馈和摘要标识。初始用户输入、最新交互、未完成调用与原始持久历史不改动。
- **明确收尾阶段。** 公司研究/复核按剩余任务及日额度预留合成与纠错空间；进入收尾后所有工具都不可用，包括 `save_research_progress`。模型直接提交最终 JSON，由控制器保存，避免“保存计划后再等一轮”。该策略不改变既有组合规划流程。配置允许的有限输出纠错不被研究无进展规则提前截断；实际研究空转与重复调用保护保留，所有纠错照常计费。
- **复用已取得的证据。** 相同证券范围、归属与研究方法的前序任务，可恢复精确保存材料，重新检查当前截止时间与引用资格。最多沿四个父任务恢复三十二个不同来源内容，超过边界拒绝；相同来源与哈希不增加独立佐证。共同来源信息可无损还原。缺失、冲突材料保留作缺口背景，明确不能用于数值事实引用；不会因某个字段缺失而拒绝整批材料，也不会升级候选为 verified。

# 个人投资 Agent 产品设计

日期：2026-10-09；2026-10-10 确认技术栈与模型独立配置，补齐研究决策、运营、组合、交互和计算设计。

状态：产品方向与技术栈已由用户确认；完整方案为设计草案，尚未实现。新增默认行为属于本次设计选择，不代替用户设置实际投资约束；技术与数据验证结果单独记录。

zcharlie 的下一阶段定位是个人投资 Agent。它理解用户的投资目标，在约定范围内自主发现机会、开展价值分析、提出买卖与仓位意见、持续检查投资逻辑并复盘；真实交易的最终决定和执行由用户掌握。

产品要解决三个持续存在的问题：短期涨跌干扰判断、发现机会后研究不足、买入后没有继续检查原来的理由。核心目标是提高投资决策过程的质量，并用长期记录检验研究过程：假设后来被证实还是证伪、证伪条件出现时复核是否按时触发、哪一步出了错。收益表现需要跟踪，但单用户的档案数量不足以做统计校准，收益不能单独证明研究过程正确。

本文定义产品目标、职责边界、体验和分期。完整设计按以下职责组织；研究行为、领域契约和计算规格分别由对应专题定义，技术设计负责集成与交付。现有功能继续按已交付契约运行，新增能力通过独立接口与版本落地。

|---|---|
| [研究与运营设计](investor-agent-research-policy.md) | 如何形成与推翻观点，何时取证或停止，怎样分配研究精力、处理组合和改进方法 |

技术方案已确定以 Python + Pydantic AI 为 Agent 核心，复用现有 Web、数据库和后台任务机制。Agent 模型独立于旧解释链路配置，可更换供应商；这是技术约束，具体要求见技术设计。框架选择不改变 A1a 公司观点、A1b 组合账本、A2 公告原文与扩大自主研究的分期。

## 已确认的产品方向

| 决定 | 含义 |
|---|---|
| Agent 是主要入口 | 用户通过对话、研究摘要与意见卡片使用产品；数据表格提供证据和深入检查能力 |
| Agent 有独立研究立场 | 可以质疑筛选结果、用户偏好和自己的旧判断，也可以在证据不足时保留意见 |
| 职责包含候选发掘和投资意见 | 可以提出买入、卖出、持有、加减仓、估值与仓位意见，并说明条件和不确定性 |
| 真实交易由用户决定和执行 | Agent 不连接券商交易权限、不提交委托；建议和用户决定都不直接改变实际持仓 |
| 研究纪律持续有效 | 每个重要观点保留依据、假设、反证和后续核查；不能事后改写原判断 |
| 数据与计算提供可核查依据 | 事实有来源和时间，计算可重现，预测假设与已发生事实分开 |

“更理性自律的自己”是待验证的产品目标。Agent 需要通过不迎合偏好、主动寻找反证、及时修正意见和遵守约束等行为体现这一目标，不能自称客观或把流畅表达当成可靠性的证明。

## 第一版范围与设计默认值

延续单用户、A 股、同源 Web、日频研究和现有部署方式。候选发掘先在已配置且有数据覆盖的目标池与用户指定标的内开展；目标池外可以保存线索，但形成意见之前须完成证券识别、数据获取与覆盖检查。

第一版分两步交付。A1a 只发布公司层面的观点：经营价值、价格隐含预期与条件性买卖看法，不假设用户有持仓或资金。A1b 再接入实际持仓与现金账本，发布针对用户组合的行动建议。任何阶段都不得假装知道用户的资产、可用资金和现有风险敞口。

以下是方案默认值，可在后续迭代调整：

- 投资方法以经营价值、价格隐含预期、反证和组合适用性为骨架；不预设用户只能投资低估值或高股息公司。
- A1a 的数值估值支持两种方法：反向 DCF 求当前价格隐含的股权现金流增长率并展示敏感性，以及已有的五年历史估值分位。反向 DCF 仅在 FCFE 口径与必需字段核验通过的范围启用；现有东财快照缺少推导所需字段，先做样本字段核对和补采，再统计适用范围，不以前置全池回填阻塞研究闭环。覆盖不足时明确限制，不能直接套用现有自由现金流字段。其他方法保留定性讨论，不生成目标价。
- 研究优先使用已有结构化数据、事件记录与用户提供的材料。公告原文目前只有标题和链接，原文获取是已知数据缺口，在 A2 接入；外部搜索通过受控来源逐步接入。
- 后台复核在数据更新完成后触发，使用 Asia/Shanghai 交易日历；新线索探索与已有持仓复核分别分配预算。
- 研究记录和 Agent 自主管理的研究队列可自动更新；用户固定关注项、实际交易和长期约束有独立权限。
- 页面提供站内提醒；外部推送需用户配置接收渠道和启用，研究内容不会自动发给第三方。

本文不设定用户的实际风险阈值、投资期限或资金用途。这些信息由首次投资约定收集，可以暂缺，但相应的个性化判断必须暴露缺口。

## 投资约定与用户记忆

投资约定是一份可查看、可修改、有版本的长期记录。它至少包含目标和期限、资金用途、投资范围、组合限制、研究偏好、自主研究权限、成本预算与通知偏好。

三类信息有不同的修改方式：

| 类别 | 示例 | 更新方式 |
|---|---|---|
| 用户明确的目标与硬约束 | 一笔资金的用途、禁止涉及的资产、用户设定的集中度上限 | 用户明确设定或修改后生效；Agent 可以提出变更建议 |
| 研究方法与可检验假设 | 如何比较同业、采用什么估值假设、模板参数是否有效 | Agent 可以研究与提出新版本；授权范围内调整研究方案，不能借此放宽硬约束 |
| 观察到的偏好与行为 | 用户经常研究某行业、经常忽略某类提醒 | 保存为待核实观察，附来源；不得自动提升为长期目标或投资事实 |

一次“我很喜欢这家公司”可以影响讲解背景，不能替代公司研究，也不能自动提高投资评价。一次实际买入只证明发生过交易，不证明原研究正确。

用户可以明确要求 Agent 记住、纠正或忘记一项偏好。删除偏好后不再用于未来个性化；历史建议中当时使用的约定版本仍作为审计依据保留。聊天记录、个人偏好和历史投资记录分别管理，避免一个删除操作产生隐含影响。

## 核心对象是持续维护的投资判断

每只持续研究的股票建立研究档案，档案可以经历多次观点变化。档案的事实依据、研究判断和行动建议分别保存，不用一段随时覆盖的总结承担所有职责。

一份重要投资判断应回答：

| 问题 | 需要留下的内容 |
|---|---|
| 为什么研究它 | 发现来源、待验证的问题、与其他机会相比的研究价值 |
| 公司怎样创造价值 | 收入和利润来源、现金转化、持续性、行业和竞争条件；关键事实有证据 |
| 价格隐含什么预期 | 当前价格的日期、适用估值方法、假设与情景结果、方法局限 |
| 为什么形成当前观点 | 支持证据、关键推断、最有力的反证、替代解释 |
| 还不知道什么 | 未解决问题、缺失或过期证据、下一项核查 |
| 对用户意味着什么 | 与投资期限、实际持仓、现金和硬约束的关系 |
| 什么时候改变观点 | 可观测的证伪条件、复核触发事件、有效期限 |

研究档案状态为“线索、研究中、持续跟踪、搁置、归档”。状态表示研究进度；“看好或看淡”“证据充分程度”“是否持仓”是独立维度。一只已持仓股票也可能处于证据不足或原判断被推翻的状态。

观点修订产生新版本，记录变化原因和新增证据。旧版本永久关联当时的数据、投资约定与组合背景。归档保留复盘能力；重新研究产生新的研究阶段，不抹掉上一次退出的理由。

## 价值分析的研究框架

第一版采用共同的研究骨架，并按行业与商业模式调整所需证据。Agent 标注每项的取证状态与适用性，不能靠固定篇幅填满报告。公司经营判断、价格判断和组合行动分别表达；支撑观点的关键事实、反证和发布强度按[研究协议](investor-agent-research-policy.md)检查。

| 研究方面 | 核心问题 | A1a 能取证的范围 |
|---|---|---|
| 商业模式与需求 | 谁付钱、为什么付钱、价值怎样转化为利润，需求变化会怎样影响经营？ | 主营构成分期表、收入与利润字段。需求变化只能定性，缺行业数据 |
| 竞争与持续性 | 支撑优势的具体证据是什么，哪些条件可能使优势消失？ | 申万行业内的毛利率、ROE 与 ROE 稳定性同业比较。优势来源只能定性 |
| 财务与现金 | 收入、利润和现金是否相互支持，改善是否可能来自一次性因素或口径变化？ | 收入、净利润、毛利率、净利率、经营与自由现金流、三年增速，东财分期表提供历史。一次性因素需要公告原文，A1a 标为待核 |
| 资产负债与资本配置 | 债务、资金需求、再投资、分红及管理层行为怎样影响股东价值？ | 负债率、股息率。再投资与管理层行为标为尚缺材料 |
| 价格与预期 | 当前价格需要哪些假设成立，与自身历史、可比公司和情景计算的关系是什么？ | 当前价、PE/PB/PS、五年估值分位、反向 DCF 隐含增长率与敏感性 |
| 下行情景与反证 | 最可能出错的关键假设是什么，影响多大，有没有更合理的解释？ | 反向 DCF 敏感性、业绩预告事件、数据冲突记录。经营层面的反证是定性推断，须标注 |
| 组合与替代选择 | 对用户现有风险暴露和资金用途有什么影响，继续持有现金或研究其他机会是否更合适？ | A1b 接入账本后才能取证。A1a 只讨论机会成本的一般原则 |

每份档案对以上七项标注三种状态之一：已取证、仅定性、尚缺材料。不适用另记适用性与理由，不算作已取证。"尚缺材料"不能用模型记忆填补；需要新数据源时记为数据缺口，作为后续取证范围的依据。第三列描述来源与计划能力，实际可发布范围按字段口径和覆盖验证收窄，尤其不能把可读的自由现金流字段等同于可运行反向 DCF。

历史估值分位、单一财务指标或综合评分可以提示问题，不能单独充当价值判断的全部依据。数据丰富程度也不等于判断正确程度。研究报告应解释哪些证据真正影响结论，哪些只是背景。

## 自主研究的工作过程

### 发现机会

机会可以来自模板筛选、财报和公告事件、同业比较、行业问题、旧档案重新评估以及用户提名。每条线索注明来源与覆盖范围。

后台探索从确定性事件流形成短名单：变化记录、业绩预告、披露日历、模板筛选差异与同业比较指标。LLM 对短名单排研究优先级，不逐只扫描目标池；用户提名可在授权范围内直接进入研究，不必先命中筛选。

Agent 可以认为未命中模板的股票值得研究，也可以认为命中股票研究价值较低。确定性筛选结果保留原始含义；Agent 的研究优先级另行展示，附比较依据，不混入原模板排名。

探索任务要有规模和停止条件。它可以在没有合适机会时输出“本轮没有值得推进的新线索”；不能为完成数量指标而制造买入观点。

### 形成研究计划

Agent 先识别会改变结论的关键问题，再安排取证。一般遵循：已有资料是否足够、缺口是什么、哪些材料可以回答、如何核查反证、何时停止。

研究深度由问题的重要程度和未知项决定。预算耗尽或必要数据不可得时，保存进展和未解决项；不得把工具失败包装成“已完成全面分析”。

### 分析与质疑

研究过程同时维护支持与反对证据。正式投资意见发布前，至少完成一次针对核心假设的反证检查，并说明反证是否足以改变判断。

固定规则验证引用、数值、日期和约束；模型负责解释商业含义和提出推断。模型的自我检查不能充当独立事实核验，也不能证明观点正确。

价格变化可以改变估值、机会成本或组合风险。Agent 应解释具体影响，不能只因为上涨就乐观、下跌就悲观，也不能机械地忽略价格。

### 发布投资意见

意见包含当前立场、理由、主要反证、适用条件、有效期限和下一次复核安排。涉及仓位时，必须引用足够新且覆盖范围明确的组合与现金快照，并由计算服务校验约束。

第一版区分两种意见，分两步交付：

- **公司层面的观点**（A1a）：对经营价值和价格吸引力的判断，可给出条件性的买卖看法，不假设用户有持仓或资金。
- **针对用户组合的行动建议**（A1b）：买入、加仓、持有、减仓、退出或保持观望，关联真实组合背景；仓位数值必须经过计算与约束校验。

意见正文中的数值通过带引用的结构化节点进入，由服务端解析与格式化。自由文本按明确的数值模式扫描，节点按主体、期间、单位和角色校验；该检查不能证明已识别所有自然语言数量表达，仍需语义评测。扫描不笼统禁用正常词语，也不以通用语义解析器作为首版依赖。规则见[领域契约](investor-agent-contracts.md)。

用户硬约束禁止的操作不能被发布为可行的行动建议，但可以解释公司的研究价值或提出修改约定的讨论。缺少某项数据时，只限制依赖它的判断；无需把所有研究一并停止。

“继续研究”和“证据不足”都是有效结果。不得把证据不足自动表达成看空，也不得将研究置信度分数解释为盈利概率。

### 持续核查与复盘

每个有效判断都需要复核计划。触发可以是新披露、经营指标变化、价格影响估值、组合变化、数据冲突或到达约定的复核日期。

触发代表“需要重新判断”。Agent 重新核查后可以维持观点、修正观点或暂时撤回意见。保持观点也要留下简要依据；没有有意义的变化时保持安静。

复盘是过程检验，不是收益评分。每次复盘回答三个问题：当时的关键假设后来被证实还是证伪；证伪条件出现时复核是否按时触发；取证、推断或约束执行的哪一步出了错。价格结果作为记录保留，覆盖未采纳的建议、搁置和退出的标的，避免只回看成功案例，但不折算成对判断能力的评分。对未采纳建议的后续价格观察不假装成真实交易收益。

## 事实与预测的边界

| 内容 | 允许的行为 | 必须满足的条件 |
|---|---|---|
| 已发生的事实 | 引用数据、披露原文或用户提供的事实 | 来源、报告期、可得时间、采集时间与核验状态明确 |
| 派生指标 | 比较、计算、情景分析 | 使用版本化计算工具，保留输入与单位 |
| 预测假设 | 对增长、盈利、估值等提出假设 | 明确是假设，说明依据、敏感性和替代情景 |
| 研究判断 | 判断价值、竞争优势、风险与优先级 | 能关联支持证据和反证；表达适用范围 |
| 买卖与仓位意见 | 提出自己的行动立场 | 区分公司观点与个性化建议，校验相关约束，记录有效期 |

未知历史数值保持未知。Agent 不得用预测或模型记忆补成已经发生的财务事实。引用存在仅证明材料可定位；还要检查材料是否支持具体主张。

估值结果是给定假设和方法下的计算，不是对未来价格的保证。具体估值方法按行业和数据适用性选择；第一版只对已支持的方法发布数值情景，其余保留定性研究与方法缺口。

外部搜索结果用于发现材料，关键主张应追溯到可保存的原文或明确的数据来源。网页与公告内的文字不能赋予 Agent 操作权限。

## 自主权限与用户操作

产品以一次明确的范围授权支持日常自主研究，避免每查一份资料都打断用户。以下是新能力的建议权限模型，当前版本尚未具备这些权限。

| 动作 | 默认方式 |
|---|---|
| 读取授权数据、解释、比较、保存研究进展 | 自主执行 |
| 在预算与范围内补充数据、发现线索、发布或修订自己的观点 | 自主执行并留记录 |
| 管理 Agent 的研究队列、创建自身复核任务 | 自主执行；不隐含移除用户固定关注项 |
| 发布站内摘要和重要变化提醒 | 在已启用研究任务内执行；去重，无变化不提醒 |
| 新增或修改研究监测条件 | 在约定权限内执行并升版本；不修改用户硬约束或既有 active 规则 |
| 修改用户固定关注项或已生效的用户规则 | 遵循用户直接指令，或对明确变更提案进行确认 |
| 修改投资约定、扩大范围、提高预算、接通新外部渠道 | 用户明确操作；既有授权不反复确认 |
| 记录用户决定与真实成交 | 用户明确陈述或提交记录；歧义只澄清相关字段 |
| 下单、撤单、控制券商账户 | 无工具、无接口、无凭证路径 |

“我同意你的建议”记录为决定，不视为已经成交。“我已经买了”只有在证券、时间、数量和价格等必要事实明确后才形成成交记录。Agent 可以起草录入内容，不能推测成交价格或日期。

用户与 Agent 意见不同时，可以保留双方的意见和理由。Agent 不反复施压，不阻止用户记录实际发生的交易；交易违反当前约定时如实记录冲突，而不是拒绝登记或篡改约定。

### 首页与对话

首页先展示与用户当前研究和持仓相关的简明摘要：哪些判断需要重看、有哪些值得推进的新线索、哪些问题还未解决、哪些事项需要用户补充。

对话默认理解当前页面的股票或比较对象。用户可以问“这家公司为什么值得关注”“这次下跌改变了什么”“你为什么不同意我”“你上次的判断哪里错了”。涉及新取证的回答显示任务进展和可取消入口。

回答先给立场和关键原因，再按需展开术语、证据、反证和计算。第一屏避免原始字段名、版本号和大量运行信息。术语解释由用户主动展开，或在首次出现时用一句话说明。

首次使用先从一个真实研究问题开始。只有当某项判断依赖投资期限、资金用途或持仓背景时，才补问相关信息并形成投资约定；已有信息不重复询问。没有填写完整画像，也能理解候选、比较公司和形成研究问题。开始前显示数据时效、模型能力验证结果和已知数据缺口。

后台研究单独启用，范围、每日预算和提醒方式放在同一张设置卡里。不启用时仍可交互研究，每次受单任务上限约束。

提醒分三类：需要用户补充、判断重大变化、普通研究进展。前两类进入首页与提醒页；普通进展只记在档案时间线里，不推送。静音只停提醒，页面要说明研究和过期检查照常进行。

用户提到的证券名称不唯一时，先列出候选让用户选择，名称与代码来自证券身份库，范围外的候选标明只能保存线索。完整研究开始前给出简短计划：问题、最先查什么、完成标准、停止条件和本次上限。解释已有观点或核查局部问题可以直接回答并附引用，不必每次建计划和发布新观点。

后台产生新版本时，旧回答保持原样，对话顶部显示"依据的观点已有更新"和变化入口。用户取消任务后显示"正在停止"，直到确认执行已经停下；浏览器断线重连后补齐进展，不取消任务。任务结束时显示停止原因和已保存的进展。

### 研究工作台

桌面布局为研究导航、对话区和可展开的档案面板；手机端通过页签切换。档案提供：当前判断、关键假设、证据与反证、估值情景、未解决问题、历史观点、用户决定与实际持仓。

比较任务使用结构化对比表。意见和事实不同样式，过期或待复核意见显式标记。证据引用能定位到具体数据日期或披露段落，不能只跳到资料首页。比较口径不满足约定时在表头提示，结论只说先研究哪家，不做总分排名。

工作台用子页签切换研究档案、线索与探索、比较、复盘。线索页展示事件流怎样经过确定性短名单与 Agent 排序得到结果，模板命中与研究优先级分列显示，并显示本轮的停止原因与上限用量。版本对比逐项标出变化，注明修订来自新证据还是只改了推断。复盘按三个问题组织，价格结果只记录不评分。

### 观点卡片的呈现

公司观点首屏依次显示：本观点回答的问题、经营判断、价格判断、研究充分度、最重要的理由、最可能改变观点的反证、附条件的看法、下一步与有效期。公司观点综合整家公司的已知情况，局部指标的正面回答不能替换当前公司观点或获得全局正面标签。公司观点不出现仓位；组合建议注明所属方案和选项，并与"不行动"并列比较。同一组合只显示一份当前正式方案，新方案明确替代旧方案，防止重复分配同一笔资金。

正文中的数字以带来源的节点呈现：等宽字体加虚线下划线，旁边小字标明事实、计算、假设或条件。点开后显示主体、期间、来源、发布与取得时间、核验状态和版本关系，可以提交"这个数据有误"。状态一律用文字标签表达，颜色只作辅助。

估值详情显示结果、终值现值占比、各项假设的来源和敏感性表。方法不适用或某格计算失败时显示原因，不用其他口径或相邻格补一个数字。

### 操作卡片

重要操作通过明确卡片展示对象和影响，例如“固定关注这只股票”“启用这条规则”“更新投资约定”“记录一笔已经发生的交易”。卡片提交后显示实际结果；工具失败不能显示成功。

普通研究笔记、内部候选和复核任务在权限内自动保存，只提供撤销、历史和管理入口。Agent 对自己的研究工作的管理不要求用户逐项审批。

记录决定提供接受、不采纳、暂缓、自行决定四个选项，理由可空，并说明决定不改变持仓。"跌到某价再买"存为条件性决定。档案操作把取消当前任务、暂停后台研究、静音提醒、归档分别列出并说明各自影响。暂停在下一执行边界停止该范围后台任务的后续动作，不影响明确的交互研究；静音只抑制主动提醒。用户归档会撤回当前意见并关闭自动重开，但保留历史、真实持仓和固定标记。

### 手机端

手机端与桌面使用相同的对象和状态。单只股票内用对话、档案、导航三个页签；导航页列出按状态分组的档案，并提供提醒、后台研究、记忆和组合方案的入口。第一版不设底部全局标签栏，这是可调整的设计默认值。

记录决定、档案操作和数字来源用底部面板，关闭后回到原位置。触控目标不小于 44 像素；首屏优先放立场、理由和下一步，证据与计算默认折叠。内容超过一屏时内容区滚动，不截断。线索、比较和复盘第一版只提供桌面布局。

## 一条完整的使用场景

以下为虚构场景，只描述产品行为。

1. Agent 从一条财报变化发现公司甲，保存线索并解释为何值得研究。它没有命中旧模板，也保留这一事实。
2. 它提出关键问题，调用结构化财报、已接入的披露事件和比较工具，记录主营改善假设与现金转化反证；A2 后接入正式披露原文取证。
3. 在支持的方法内进行估值情景计算，形成公司层面的明确观点，展示最可能让它改主意的证据。A1b 之后再结合用户组合给出行动建议。
4. 用户决定暂不行动。系统保留这个决定，继续检查研究计划中的问题，不把“未采纳”作为错误训练信号。
5. 用户后来明确记录一笔已完成的交易。系统更新实际持仓，同时保留这笔交易是否遵循原建议。
6. 价格下跌触发复核。Agent 检查估值、经营证据和组合限制；可以维持或改变观点，并解释差异。
7. 新披露推翻关键假设，Agent 修订意见并通知用户。它保留旧版依据，安排事后复盘。

第一版的验收必须贯穿这条链路，而不能只证明能在聊天框解释一张表。A1a 验收覆盖第 1 到 4 步和第 6 到 7 步中不依赖组合的部分；第 5 步与组合校验在 A1b 验收。

## 对现有产品的调整

| 现有设计 | 新设计中的处理 |
|---|---|
| 只有已批准规则触发才能产生操作意见 | 新增独立的投资意见记录；规则事件是证据与复核触发之一 |

| 候选默认到期归档 | 候选线索可以到期；正在持续研究或已有持仓的档案不能随候选到期消失 |

| 披露与证据是可选的后期能力 | 不再可选。A1a 先用已有结构化数据与事件取证；公告原文获取作为已知数据缺口在 A2 接入 |

| 主要关注跟随率与晋级转化率 | 增加证据正确性、反证覆盖、过期意见处理、约束遵守、理解成本与前瞻结果评估；不以说服用户为优化目标 |

保留 PIT 快照、确定性因子与评分、规则执行、数据健康、队列、幂等、变更记录和审计制品。既有分数是一个模型下的分析结果，不是整个产品的最终判断。

## 分阶段交付

| 阶段 | 用户获得的结果 | 退出条件 |
|---|---|---|
| 前置验证 | 无用户可见功能 | Pydantic AI 框架内的工具与输出模式探针通过，确定该端点可用的输出模式与 profile；历史分位覆盖率与现金流原始字段可得率已测，FCFE 口径覆盖在 A1a 补字段后统计；结果决定模型配置与 A1a 范围 |
| A0 研究契约与执行基础 | 可配置投资约定，任务、证据、判断对象具备可靠存储 | 权限、版本、取消、幂等、缺失和过期处理的关键契约可验证；此阶段不宣称完整 Agent 已上线 |
| A1a 公司观点闭环 | 对有限研究范围，完成发现、取证、公司层面观点、决定记录、持续复核和过程复盘 | 独立观点包含有依据的条件性买卖看法；估值按已验证范围启用且缺口可见；贯穿虚构场景中不依赖组合的步骤并通过失败路径验收 |
| A1b 组合与仓位建议 | 录入实际持仓与现金，比较不行动与有限行动选项，获得针对组合的建议 | 账本冲销与覆盖范围正确；同一方案共享现金和约束；仓位数值经计算校验；建议和决定都不能生成成交 |
| A2 持续自主研究 | 在范围与预算内探索新机会并维护多份研究档案，接入公告原文，主动通知重要变化 | 去重、优先级、成本、工具失败和用户控制可用；无变化保持安静 |
| A3 组合与方法改进 | 扩展多资金用途的机会成本比较，复盘方法并提出改进 | 方法有 proposed、evaluating、shadow、active 等生命周期；新旧方法经过评估和明确批准，不能自动修改硬约束或重写历史 |

前置验证只回答不需要任务层就能回答的问题，结果约束模型集成和估值适用范围；业务契约、固定样本和页面设计可独立推进。故障恢复、等待与取消属于 A0 任务基础的验收。已有 SDK 与单模型框架探针记录在技术设计中，不能据此宣称跨模型验证和 A0 全部通过。A1a 的范围可以小，但必须具备独立判断和后续核查。A2 扩大自主研究的规模和覆盖，不以增加多个 Agent 角色作为完成标准。工作包拆分与依赖见技术设计。

## 设计覆盖与验证边界

研究与运营专题覆盖证据到观点的门槛、研究生命周期、组合方案、原文取证、记忆与方法改进；领域契约覆盖跨会话交互、状态与依赖传播、真实账本和固定场景；估值专题固定计算口径与不适用行为。这些设计决策形成可评审的完整草案。实际模型质量、数据覆盖、成本和任务恢复仍需实施验证，不属于已经实现或已经通过的能力。

第一版至少验证：用户能理解当前立场、依据、反证和下一步；每条重要事实可定位；变化会更新对应判断；过期意见不作为当前建议显示；实际持仓不会由建议自动生成；用户偏好不会直接改变事实；工具失败会留下真实状态。

固定评测集中的越权写入、虚构事实数值、伪造成交和静默改写历史必须为零。事实引用有效率与引用是否支持主张分别评估。通过测试表示对已覆盖场景的验证，不代表生产环境永不出错。

模型端点能力、框架输出模式和估值方法的数据覆盖在前置验证解决；故障恢复在 A0 任务基础验收。上线前还需通过配置或实施验证的细节包括：用户的投资约定、实际成本与延迟预算；公告原文获取与解析覆盖在 A2 前验证。它们影响具体能力范围，不改变已确认的产品方向。

首次内部试用使用用户于 2026-10-10 指定的招商银行、海康威视、国电南瑞。用户未明确指定各公司的场景及理由，AG20 根据真实证据与历史版本确定下表的场景覆盖，不预设投资结论；缺少可验证场景时如实记录缺口。设计和工程回归先使用[固定场景集](investor-agent-contracts.md)与脱敏 fixture。不以用户最终是否买入作为成功标准；样本选择不等同于人工质量验收或开放入口的批准。

| 情况 | 公司 | 验证要点 |
|---|---|---|
| 值得研究 | AG20 从上述样本按证据确定 | 线索来源可追溯，七项研究方面的取证状态标注准确，公司观点含反证与复核计划 |
| 证据不足 | AG20 从上述样本按证据确定 | 输出“继续研究”或“证据不足”，不表达为看空，数据缺口列出 |
| 原判断失效 | AG20 从上述样本按证据确定 | 新证据触发复核，观点修订为新版本，旧版依据保留，过期意见从当前视图移除 |

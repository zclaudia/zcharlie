# 个人投资 Agent 研究与运营设计

日期：2026-10-10。状态：完整设计草案，尚未实现；本次补充的默认行为可在评审中调整，不代表用户已设置实际投资约束。

Agent 的长期职责是维护有依据、能被反驳、会随证据变化的投资判断。研究结论的强度由证据决定，研究投入由问题的重要性和可回答程度决定。用户是否采纳、是否喜欢某家公司以及短期盈亏，都不直接改变事实或研究标准。

本文规定研究判断、自主运营、组合决策和方法改进的行为。产品范围见[产品设计](investor-agent-design.md)，状态、权限和交互契约见[领域契约与交互流程](investor-agent-contracts.md)，数值方法见[估值计算设计](investor-agent-valuation.md)。框架与运行机制以[技术设计](investor-agent-architecture.md)为准。

## 研究判断的形成

### 分开回答三个问题

| 判断 | 回答的问题 | 输出与边界 |
|---|---|---|
| 公司经营判断 | 创造价值的能力和主要风险怎样变化 | favorable、mixed、unfavorable、undetermined；不由股价或用户态度直接决定 |
| 价格判断 | 当前价格要求哪些假设成立，这些要求是否苛刻 | attractive、balanced、demanding、undetermined；明确价格日期、方法与适用限制 |
| 组合行动 | 对已知的用户资金与持仓，是否应该行动 | buy、add、hold、reduce、exit、wait、further_research；只在 A1b 后发布 |

前两项构成 `company_view`。公司观点可表达附条件的买入或卖出看法，使用 `conditional_actions` 写明“如果哪些事实或假设成立，可以考虑什么”；不出现“你应加到多少仓位”。同一家公司的经营判断可以偏正面而价格要求苛刻，也可以经营承压但暂时无法判断价格。

普通公司研究与公司观点发布不以个人投资约定为前提；其范围来自本次用户授权的证券对象，证据、数值、反证与发布校验保持不变。新公司观点默认不绑定个人约定，已有显式关联约定的观点仍检查原关联版本与相关依赖。个人配置建议必须先具备投资约定、实际账户上下文及适用约束；后台执行仍单独检查约定、开关、范围与预算。公司研究产物和监测条件本身不授予后台执行权限。

研究充分度另存为 `insufficient | bounded | sufficient_for_scope`，描述对本次问题的支撑程度，不是公司质量分或盈利概率。七项研究维度继续使用“已取证、仅定性、尚缺材料”；不适用通过 `applicable=false` 与理由表达，不把缺数据标为不适用。

### 按问题选择研究深度

先区分解释已有结果、核查局部问题、完整公司研究、观点复核与组合研究。解释和局部核查复用有效证据，保存回答、引用及必要的研究笔记，不必启动完整研究计划、重填七项维度或发布新意见。研究笔记作为消息或任务产物保存，不新增独立的笔记工作流。

完整公司研究和正式观点修订才执行下列协议。局部问题发现关键反证时，先使受影响旧意见受限，再安排正式复核；不能用一条“现金转化偏正面”的回答替换整家公司的当前 thesis。`question_scope` 用于明确判断边界，不能成为降低完整公司观点发布门槛的理由。

| 步骤 | Agent 必须回答 | 保存的结果 |
|---|---|---|
| 确定问题 | 用户要解释已有观点、检查变化，还是形成新观点 | 问题、范围、已有观点、完成标准和预算 |
| 建立解释 | 当前现象可能有哪些解释，哪一项最影响结论 | 核心假设、最强替代解释、关键未知项 |
| 安排取证 | 哪个证据最可能区分这些解释，现有工具能否取得 | 按重要性排序的研究计划，每项有可观察结果与停止条件 |
| 核验与计算 | 证据的主体、时间和口径是否一致，哪些数字是计算或假设 | 证据、冲突、计算记录和七项取证状态 |
| 反证检查 | 假如当前观点错了，最可能错在哪里 | 对核心假设的反对证据、已查来源、仍未解决的问题 |
| 形成观点 | 证据支持到什么程度，哪些条件会改变判断 | 公司观点或组合建议、边界、有效期限和监测条件 |
| 发布或保存进展 | 发布门槛是否满足，继续研究是否仍有价值 | 正式版本，或带具体原因的草稿与后续任务 |

“关键”有可审查含义：移除该主张或让它反向成立，会改变观点方向、适用条件、数值情景或组合行动，则为关键主张。Agent 必须给出这项影响，不能把难以核实的内容降为背景以绕过发布门槛。审查步骤检查遗漏；语义评测另行检验，系统不声称能机械证明所有论证。

计划优先回答能改变决定的问题。第一轮不默认生成长报告；先完成足以回答当前问题的证据链，再提出深入研究的价值。跨公司比较使用相同报告期、口径与问题；无法统一时并列展示差异，不硬排总分。

### 发布强度与证据门槛

| 可发布结果 | 最低条件 | 不满足时的行为 |
|---|---|---|
| 解释、术语说明、研究进展 | 引用存在且内容准确；一般概念不冒充公司事实 | 指出无法回答的具体部分；不生成正式投资意见 |
| 继续研究或暂不判断 | 能说明关键问题、已知事实、缺口及其影响 | 可以发布 `undetermined` 的公司观点；不把缺口表达为负面判断 |
| 有明确方向的公司判断 | 支撑方向的关键事实可核验；没有未处理的关键来源冲突；完成反证检查 | 缩小结论适用范围，或回到暂不判断 |
| 附条件的买卖看法 | 公司判断有依据；价格判断或明确的风险退出理由有依据；条件可观察，关键未知项已限定 | 可以发表公司经营判断，暂不发表依赖缺口的买卖看法 |
| 组合行动建议 | 公司观点仍有效，或行动仅为解除已知组合硬约束；组合、现金和约束足以支撑该行动；计算与整个方案一致 | 保留公司观点与局部风险解释，请求必要信息，不输出受影响的仓位数字；硬约束例外不能用于买入或加仓 |

不是所有维度都必须有完整原文才能形成有限观点。A1a 可以判断“现有财务证据支持现金转化改善”；若买入逻辑依赖“改善来自持久竞争优势”，却只有未经取证的叙事，则不能发布据此成立的买入看法。假设可以用于敏感性情景，不能替代关键历史事实。

“仅定性”表示存在可说明的分析依据但不适合量化，必须区分来源支持与分析推断。没有证据的公司特定断言归入“尚缺材料”。“估值分位低”只能说明历史相对位置，不能独立推出便宜；反向 DCF 的隐含增长不是 Agent 对增长的预测。

发布由机械校验与结构化审查共同约束：前者阻止失效引用、错误数值、过期上下文和越权；后者记录关键事实是否支撑结论、反证是否实质相关。审查发现关键问题时退回，不以模型自评“有信心”放行。确定性校验通过不等于投资判断正确。

### 分歧与观点修订

| 新信息 | 必须采取的行为 |
|---|---|
| 只有价格变化 | 更新价格与隐含预期；说明经营判断是否保持，不能编造经营原因 |
| 新材料支持旧假设 | 记录假设获得何种支持；同一事实被多家转载不算多份独立证据 |
| 关键假设被证伪 | 先停止把受影响意见作为当前建议，再研究维持、修订或撤回；不直接生成卖出指令 |
| 来源冲突或更正 | 保留双方和更正关系；能按明确来源规则解决则记录理由，否则相关结论暂缓 |
| 用户提出新的事实 | 作为用户来源材料保存并核验；更正研究事实后重新判断 |
| 用户只表达赞同或反对 | 解释分歧和可改变判断的证据；不无依据迎合，也不反复施压 |
| 原证据不变但推断改变 | 新版本标记 `reasoning_revision`，列出原推断的问题；不能伪装成收到新证据 |

复核结果为 `maintain | revise | withdraw | inconclusive`。维持观点保存 review event，不复制相同 thesis。仍有效、未受限的意见可在复核通过后追加 `extended` 事件；已过期或待复核的意见，重新成立时必须发布新 recommendation，不能用续期掩盖中间的失效。依据、条件或监测变化时也发布新 recommendation。完整规则以领域契约为准；新观点发布与旧观点被替代同事务完成。

## 自主运营与研究队列

### 首次启用和日常节奏

用户从候选、单股页面或自由提问进入即可开始一次有限研究。首次不要求填写完整投资画像；涉及资金用途或组合判断时再补充必要信息。证券身份不明确时先消歧，不能把简称直接写成一只确定股票。

持续后台研究单独启用，范围、每日预算与站内提醒方式在一张设置卡中说明。范围可以使用用户明确选定的现有目标池；缺少后台额度时仍可进行有单任务上限的交互研究，不静默启动付费探索。模型选择与凭证沿用独立 Agent 配置，投资约定不保存密钥。

日常工作由已完成的数据批次与到期计划驱动。调度先确认来源是否更新，再对受影响假设做便宜的确定性检查；只有出现待回答问题时才启动模型研究。没有问题时不生成“今日分析”填充界面。

### 研究档案的状态转换

| 当前状态 | 进入下一状态的条件 | 系统动作 |
|---|---|---|
| lead 线索 | 用户要求研究，或线索在范围内且有可回答的问题 | 进入 researching，建立问题和计划 |
| researching 研究中 | 已形成可用观点并有后续观察价值 | 进入 tracking，启用复核计划 |
| researching 研究中 | 关键材料不可得、预算耗尽且没有待完成子任务，或当前研究价值较低 | 进入 parked，保存原因和重新启动条件 |
| tracking 持续跟踪 | 发生需深入核查的变化 | 进入 researching；意见有效性单独判断 |
| tracking 持续跟踪 | 目前无需投入且不承担持续监测责任 | 进入 parked，保留低成本的重启条件 |
| parked 搁置 | 新证据满足重启条件、用户请求，或获得原先缺失材料 | 进入 researching，不重新编造发现来源 |
| lead 或 parked | 重复线索合并、超出研究范围，或用户结束关注 | 进入 archived，记录原因与未完成项 |
| archived 归档 | 用户重新研究，或系统归档的档案在授权范围内出现明确新线索 | 增加研究 episode，复用同一 case；用户主动归档的档案不得由探索任务自行重开 |

`waiting_data` 属于任务状态，等待中的研究档案仍为 researching。Agent 不能自动搁置或归档用户固定关注项、已有持仓或承载有效意见的档案来逃避复核；这些档案无材料时保留监测责任，并显示覆盖缺口。用户可暂停后台研究，但旧意见的时效检查继续生效。

用户明确归档时，停止该档案的研究计划并撤回仍有效的意见，保留历史和真实持仓。组合服务对已知持仓的约束检查不因研究归档而消失；组合持续研究是否运行仍取决于其独立授权。归档不隐含取消用户固定标记，界面可从固定关注中看到归档状态。

归档记录 actor 与 reason，用户归档同时关闭该 case 的自动重开权限。暂停则停止该范围后续后台动作，并停止已在运行的后台任务在下个执行边界发起新调用或发布；它不取消用户明确发起的交互研究。静音只抑制主动提醒，页面状态与历史仍可查。恢复不重放暂停期间全部事件，只检查当前有效性并合并尚未解决的变化。

### 优先级与停止规则

调度优先处理关键证据失效和组合硬约束冲突，再处理当前用户请求、到期复核与计划研究，最后探索新机会。交互任务使用独立 worker 配额，不能被批量探索饿死。每一类内部按截止时间、等待时间和证据变化的重要性排序；模型可解释研究价值，不能把研究顺序伪装成股票收益排名。

后台探索从确定性短名单开始，默认每批最多审阅 20 条线索、最多新建 3 个研究任务；用户明确提名的公司在授权范围内可直接研究，不必先命中短名单。重复证券合并，未入选线索保存理由和再次评估条件。这两个上限保存在投资约定的研究授权部分，默认值来自运行时设置；它们是工程限额，不是每批必须产出的数量。探索与复核预算分账且受同一每日总额约束；Agent 不自行挪用或提高用户授权额度。

单次研究在以下任一条件结束：问题已经回答；关键材料确定不可得；连续两轮未取得新证据或解决新问题；同参数同版本工具请求重复且无新依赖；达到调用、token、时间或金额上限。保留 `answered | evidence_blocked | no_progress | budget_exhausted | cancelled | failed` 原因。预算耗尽不自动跨日续跑；是否继续由仍有效的研究计划和下一日额度重新决定。

next_review_at 默认为发布后 7 个自然日，valid_until 默认为发布后 14 个自然日，复核安排必须早于失效期限；遇到更早的披露或假设检查时点则提前。这是可配置的工程默认值，不保证意见在此期间一直适用。复核逾期单独显示；达到 valid_until 显示已过期。价格、关键证据和约束变化可使意见更早受限，不因期限未到而使用过期行情。续期从本次实际核查时间计算，保留原计划与逾期记录，不因拥塞改写原始期限。

### 监测和通知

A1a 使用 `snapshot_committed` 的字段差异与 `calendar_due` 两类入口。字段差异既能表达价格变化，也能表达新的财务期间；A2 再增加可定位的公告材料事件。每个 monitor 指向明确假设，描述触发后要回答的问题，而不只是给出一个提醒标题。

条件只接受已注册字段、比较运算、同口径期间比较、事件类型和时间。缺字段返回 unknown，不能当成 false。定性事件只触发取证；模型不能生成任意 SQL 或 Python 作为监测条件。Agent 修改自己的 monitor 会升版本，不能关闭仍被有效意见引用的必要监测而不先修订意见。

同 case 同一批输入变化合并为一次复核；运行期间出现更新则登记 dirty 标记，结束后处理尚未消费的变化。自动任务仅在问题、关键证据、方法、相关约定字段、相关组合版本及检查时点均相同且已有可用结果时复用；用户提出新问题或要求检查原推断时不能被“证据相同”阻止。没有实质变化的检查与正常续期只进时间线；观点、关键证据、受限状态或所需用户动作变化才发站内提醒。同一次变化的受限提示与后续复核结果更新同一提醒。

提醒分为需要用户补充、判断重大变化、普通研究进展。前两类显示在首页，普通进展进入档案时间线。用户暂不采纳后不因同一原因重复劝说；新的关键证据仍可通知。静音只影响提醒，不取消研究责任；暂停研究、归档、取消当前任务分别是独立操作。

## 组合决策与资金分配

### 组合信息的最低要求

A1b 首先支持一个用户明确声明范围的人民币 A 股现金组合，不默认代表全部个人资产。需要起点日期、持仓数量、现金与其可用性、未处理交易或公司行动，以及适用的用户约束。成本缺失不妨碍当前市值与暴露计算，但禁止展示无法还原的收益。部分组合可以解释局部持仓事实，不输出整体目标仓位。

形成买入或加仓金额前必须知道可用现金、资金保留要求和相关集中度约束。缺少这些信息时给公司层面的条件性看法，并集中补问受影响的字段。Agent 不替用户推断风险承受能力，也不把未填写上限解释成无限额。

### 一个方案内比较行动

每次组合研究固定同一个组合快照，生成一个 `portfolio_plan`。方案至少比较“不行动”，再比较有证据支持的可行替代项；可以选择保留现金，不为使用全部资金而买入。持有现金的收益默认未知，不能编造利率；转换成本不明确时显示其缺口，不能当成零。

单项买卖建议必须属于方案的一个互斥选项。多个股票的建议共享资金与暴露计算，不能各自重复使用全部现金。资金来源依赖卖出时明确标为条件，实际可用性由用户录入的已完成事实和资金状态决定；方案不声称能完成成交。

同一组合同时最多有一份当前正式方案；不同会话的新方案发布时，原子校验组合 revision，并显式替代整份旧方案。讨论中的替代方案保留为草稿，不能同时呈现为可以叠加执行的建议。采纳仅记录决定，不预留真实现金；任何实际成交或现金变化都使相关剩余行动重新接受检查。

| 行动 | 必须说明的理由 |
|---|---|
| buy 或 add | 公司与价格证据支持；为何比不行动更合适；资金来源、风险与失败条件 |
| hold | 原假设仍成立，继续占用资金的依据；买入成本不作为单独理由 |
| reduce 或 exit | 假设失效、价格要求变化或组合限制中的具体原因；不把下跌本身当成经营恶化 |
| wait 或 further_research | 等待的是哪项材料、条件或约束；何时重新检查 |

A1b 通过解释清楚的有限选项比较资金用途，不进行全目标池最优组合搜索，不生成未经校准的收益概率。先检查硬约束，再比较证据、下行情景、机会成本和转换成本；不能用一个综合分自动抵消硬约束。存在取舍时说明，不伪装成唯一正确答案。

### 仓位数字的生成

模型可以提出带理由的目标暴露区间，区间是方案假设，必须记录来源，不被描述成计算出的“最优仓位”。确定性计算服务从同一组合和价格基准出发，按各选项的费用与资金变化计算行动后的净资产、数量及暴露，再检查现金保留、单股和行业限额；不能忽略费用对分母的影响。结果返回可行部分、约束冲突及所依赖的假设。

数量换算使用版本化证券交易单位资料，不能默认所有证券同一手数；无法取得时只展示经过约束检查的金额或比例情景，不生成数量。费用、停牌、未完成公司行动或可用现金未知时，对相应行动标为受限。费用未明时可展示明确标注的未扣费情景，不能称“约束全部通过”；只有费用规则或有来源的保守费用上界已纳入计算时才判定资金可行。实际成交价格与数量必须来自用户事实。

组合变化使相关方案待复核；用户采纳方案只生成决定。用户实际执行一部分后，用新的组合快照评估剩余动作，不能假定旧计划仍然可整体执行。超出约定的真实交易仍如实入账并记录冲突。

A3 扩展为多个资金用途之间的机会成本与方案比较，仍先依赖用户明确的资金分区。首版不跨未知账户净额计算，不引入杠杆、衍生品、空头和自动交易。

## 取证能力的扩展

A1a 的正式来源是已有结构化快照、事件，以及能保存与定位的用户文本材料。用户文本标为 user_report，不直接升为已核实公司事实。A2 扩展流程为：发现公告 → 校验证券与披露标识 → 保存原件及 hash → 解析并定位 → 提取候选事实 → 核验 → 关联主张 → 触发复核。

| 材料或异常 | 处理规则 |
|---|---|
| 正式披露与更正公告 | 原件不可变；更正形成新记录和 supersedes 关系，不覆盖旧材料 |
| PDF 文本与表格、HTML | 保存页码或稳定段落/表格定位、解析器版本；先验证单位、期间、合并口径 |
| 扫描件与 OCR | OCR 结果为候选；关键数值未经原件定位和核验不得进入已核实事实 |
| 新闻、第三方研究与搜索摘要 | 作为发现或明确归属的观点来源；关键公司事实追溯原始材料，搜索摘要不能代替正文 |
| 官方原文与供应商数据冲突 | 比较发布时间、口径和更正关系；有明确依据才解决，否则保留冲突 |
| 下载或解析失败 | 标明失败阶段和可重试原因；保留已有研究，不宣称没有新信息 |

证据先按证券、时间、字段和关键词检索，按引用关系补齐上下文。长文只发送相关片段及定位信息给模型；片段不足时获取相邻段落。全文检索不能替代精确数值工具。只有检索评测证明现有方法不足时才引入向量检索，其结果仍需回到可定位原件。

受控来源清单由应用配置，模型只能提出新来源需求。外部下载不接受模型随意指定内部网地址；部署者配置的内部数据服务走独立的已授权适配器。来源清单、下载大小、解析超时和原文发送范围有应用限制。

## 记忆与研究方法改进

### 记住什么以及怎样遗忘

| 记录 | 权威来源 | 使用与更新 |
|---|---|---|
| 当前对话上下文 | 本会话消息及明确绑定对象 | 有限窗口与可重建摘要；摘要不产生新的事实 |
| 公司长期判断 | case、thesis、evidence、review | 按对象与版本检索，不把聊天摘要当作新的公司证据 |
| 用户明确偏好 | 用户原始陈述及确认范围 | 影响讲解和研究范围；硬约束通过 mandate 修订 |
| 行为观察 | 多次可定位交互，状态为待核实 | 可据此温和提问，不能自动推断风险偏好或改变硬约束 |
| 方法教训 | 已完成复盘及原始研究版本 | 先成为带适用范围的候选规则，经评估后进入方法版本 |

当前任务优先载入相关约定、最新有效观点、关键证据和未解决问题；用户偏好只取与当前交互有关的部分。冲突的用户明确约定以有效 revision 为准，无法判断指代时澄清。过期观察不进入新上下文，观察默认 90 天后需重新评估；用户明确偏好保持到被纠正或删除。

“忘记我的偏好”使该偏好失效，并清除可用于个性化的摘要与检索条目。上下文装配按撤销记录过滤原始消息中的相应片段及派生摘要，不能从旧聊天重新提取已撤销偏好；在途任务发送后续请求或回答前检查记忆 revision。旧投资判断保留当时引用的约定，仅供解释历史依据。删除对话、撤销偏好、归档研究和删除本地全部数据分别呈现，不能由一个“忘记”隐含执行全部操作。供应商侧数据处理遵循所选模型服务的配置，产品不承诺本地删除能撤回已经发出的请求。

### 从错误到方法版本

复盘分别判断事实错误、口径错误、推断不足、监测遗漏、约束执行错误和正常不确定性。假设结果为 supported、refuted 或 unresolved；未发生预期事件不自动等于被证伪。必须检查当时可得信息，不能用后来知道的结果指责当时没有材料。

单次盈亏只形成案例。可推广的教训写成 `method_change_proposal`：具体失败模式、适用范围、拟改变的步骤、支持与反对样本、可能副作用和回退方式。Agent 可以在已有授权内改变当前案例的研究问题和顺序；不能自己修改全局提示词、计算公式、发布门槛或运行代码。

方法状态为 proposed → evaluating → shadow → active，失败进入 rejected，停用进入 retired。A3 在固定历史材料集与后续观察中比较新旧方法；shadow 只生成隔离输出，不能覆盖正式观点或发送正式提醒。历史集生成不用于声称历史投资收益。

全局研究方法启用需要用户批准明确变更；公式、工具权限和程序变更通过正常开发发布。评价至少包含一个原失败样本和适用范围之外的反例，不能只证明对某只股票变好。批准生效后仅新任务使用新版本；旧输出保留原方法标记。回退影响未来运行，不删除新方法曾发布的历史。

## 质量评估与完整场景

### 评估分层

确定性回归检查引用、数字、权限、状态、去重与账本；真实模型评测检查研究内容。相同材料下更换用户态度，核心事实与方向不应无证据改变；允许措辞和解释角度变化。两个模型的合理观点可以不同，必须各自满足证据与边界要求。

| 人工评估维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 事实与结论关系 | 关键事实虚构或不支持结论 | 主要引用正确但存在遗漏 | 关键论点可定位，范围与材料一致 |
| 研究深度 | 复述指标或套话 | 回答部分关键问题 | 解释关键驱动、替代解释与未解决项 |
| 反证质量 | 无反证或装饰性风险提示 | 有反证但未说明影响 | 说明最可能推翻观点的证据和改变方式 |
| 不迎合与自我修订 | 随用户态度或价格无依据改变 | 判断基本稳定但说明不足 | 有依据坚持或修订，并保留先前错误 |
| 可理解与可继续 | 用户不知当前结论或下一步 | 可理解但条件不够清楚 | 能复述立场、主要理由、反证和下一步 |

首版固定集的“事实与结论关系”须为 2 分；有方向的正式观点，其“反证质量”也须为 2 分，其余适用维度至少 1 分。解释或明确证据不足的样本可标记不适用的维度并给出理由，不能用不适用掩盖已发表的方向性结论。关键事实错误与硬约束违规必须为零，其他维度不能抵消失败项。分数用于比较研究输出，不作为投资胜率或用户画像评分。评审记录模型、方法、材料集版本与评审者；模型辅助评审不能单独签署语义通过。

运行指标记录复核按期完成数/到期数、证据可定位数/应引用数、事实纠错、预算耗尽、重复通知和受限研究数，显示分母与未知项。假设证伪之后系统是否按时响应，和假设本身是否预测准确分开统计。未采纳、搁置和归档案例同样保留，用户采纳率不作为优化目标。

### 一条贯穿全部阶段的虚构案例

| 场景 | Agent 的判断和动作 | 用户可见结果 |
|---|---|---|
| 公司甲收入改善但现金转化不明 | 从事件短名单建档，提出增长质量问题 | 解释为什么值得研究，不直接称为买入机会 |
| 财务材料支持改善但持久性未知 | 发布有限的经营判断；价格方法适用才计算，列出待核假设 | 看见依据、局限、反证和条件性看法 |
| 用户表示喜欢并决定暂不行动 | 保存 defer 决定，保持原研究标准 | 不被要求重复批准研究，也不被持续劝买 |
| 股价下跌而经营证据未变 | 检查价格条件、更新计算，保持有依据的经营判断 | 明白价格影响在哪里，经营结论为何不变 |
| 用户录入实际买入事实 | A1b 校验事实后入账，以新组合重新研究 | 决定、建议、成交三条记录可区分 |
| 新公告推翻现金转化假设 | A2 取证；使依赖该假设的意见待复核，形成新判断 | 收到一次包含新旧依据的变化提醒 |
| 复盘发现持续忽略某类反证 | A3 形成方法变更提案并用反例检验 | 用户能审查改什么、为什么、如何回退 |

这条场景在 A1a 用结构化财务变化和固定材料完成不依赖账本、公告原文的部分；后续阶段替换为相应的真实输入能力，沿用同一判断与版本契约。功能覆盖矩阵与失败路径见[领域契约](investor-agent-contracts.md)。

# 行业与同行参照技术设计审查

日期：2026-10-12。结论：修订后的[技术设计](industry-peer-technical-design.md)可以作为首期开发基线，先以本地固定证据完成接入、计算和页面，再做 Agent 离线契约验证。持续在线补采和真实外部 Agent 的启用仍需完成对应来源条件与验收。以下修正均为设计约定，尚未实现为应用代码。

审查依据是[已确认范围](industry-peer-scope-draft.md)、当前仓库实际实现以及[本地验证材料](../../research/industry-data-validation/evidence/run-02/report.html)。保留白酒、完整年度、三项描述性比较，不扩展评分、行业轮动或历史回测。

## 发现的问题与已修正约定

P1 表示遗漏会造成错误引用、权限放宽、版本混用或首期链路无法完成；P2 表示不准确的复用假设或可避免的额外建设。优先级针对设计，不代表已经确认线上故障。

## 开发与启用条件

可以开始实现固定 19 家、2025 年的离线链路。已保存材料支持六个核心字段的 114 项对照与三项统计基准；开发导入仍须验证原件 hash、年度、表头、单位和当期列，不能直接信任研究 JSON 的 matched 标志。新年度自动核对能力并未得到证明。

开发顺序为固定证据与纯计算、限定任务离线验证、页面、Agent 离线接入。接口在线稳定性、来源保存与展示条件、外部模型发送范围，以及真实解释质量分别作为对应能力启用的验收项，不阻塞固定证据驱动的实现。功能默认关闭，旧个股评分保持兼容。

尚需在实现中证明的关键行为是：原件核对与修订失效、跨主体统计授权、完整依赖的语义材料绑定、任务 cutoff、比较与反证规则、续期拒绝、并发批次发布及备份恢复。离线计算成功不能代替这些应用验收。

本次完成代码对照和文档一致性检查，没有修改应用代码、执行迁移、调用数据接口或运行应用测试。因此可以进入开发，不应将本结论解读为可以直接启用线上能力。

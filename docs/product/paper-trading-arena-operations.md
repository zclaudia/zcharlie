# 模拟实验使用与运行

这是 A 股主板普通股的前瞻日线模拟。用户固定股票池、资金、交易规则和参赛模型，每个参赛者拥有独立虚拟账户；系统同时建立现金和等权买入持有基准。研究资料按轮次冻结，模型不能读取其他参赛者的决策或记忆。源码、接口与验收记录见[实施任务](plans/paper-trading-arena-implementation.md)，调研依据见[设计](paper-trading-arena-design.md)。

## 启动条件

1. 在目标环境执行 `ia migrate up`，应用迁移 `061`（文件 `061_simulation.py`）。迁移新增模拟表，不转换真实组合账本。
2. API、采集 worker、Agent worker、scheduler 均需运行。Docker Compose 已加入任务类型；手动启动时，Agent worker 的 `--kinds` 需包含 `simulation_decide,simulation_review`，采集 worker 需包含 `simulation_cycle`，保留原有任务类型。
3. 在模型设置中配置参赛模型。实验保存模型选择、参数及方法和提示词的摘要；供应商凭证继续由设置服务管理。修改模型配置后，原实验会阻止使用发生变化的配置，需要创建新的实验版本。更新凭证本身不把密钥写进实验。
4. 已核对交易日历需覆盖观察日、下一执行日及买入批次的下一可卖交易日。API 创建和就绪诊断会检查最终观察日之后的执行日及其下一可卖交易日均已核验；页面最大观察日因此取已核验日历的倒数第三个交易日。季末日期即使为周末／休市日，也保守要求其后两个已核验交易日。实际结算还会再次验证可卖日覆盖。未知年份阻塞，不按工作日猜测。证券须已存在于本地目录。

## 页面操作

入口为 `/app/simulations`，使用现有 Web 登录。创建时选择股票、参赛模型、起止日期、资金和日频或周频。各 Agent 使用相同的实验交易规则，基准由系统加入。只比较模型时保持方法和预算一致；参数变动应另建实验，避免把不同条件的结果混在一起。

首版 Web 与友好创建 API 使用固定的内置研究方法，提供模型比较和综合比较。领域与运行层保留冻结不同方法正文的能力，自定义方法编辑和发布入口尚未开放。

友好创建默认 `memory_policy=none`：复盘仍会记录和展示，但不会自动进入后续模型输入。领域／运行层显式声明 `matured_own_reviews` 时，才允许在成熟且可知时间到达后读取本人复盘；当前页面没有该策略编辑入口。

实验冻结的是供应商／模型标识、调用参数及研究方法，不能保证供应商不更新底层权重。运行时没有取得的返回模型版本保留为空，不伪造版本证据。

创建后可先刷新资料，查看数据缺口，再启动实验。启动会允许 worker 在实验规则和预算内调用所选模型。页面展示运行状态、轮次、独立持仓、决策理由、订单与成交、净值、复盘和调用成本；数据不完整时显示原因。运行按钮仅把任务入队，HTTP 请求不等待行情采集或模型响应。

暂停停止新决策和付费模型复盘，并撤销尚未到执行时点的订单。已发生经济时段的订单继续按原规则结算，不能通过暂停抹去结果；暂停账户继续估值。已发出的远端请求可能仍完成并产生费用；暂停不能撤回已发出的供应商工作。结束不按最后收盘价虚构清仓；仍有已发生订单时继续处理结算，全部处理完成后不再自动持续生成新轮次和每日估值。导出包含实验规则、共同资料、账户、决策、订单、成交、账本、净值、复盘与成本记录，保留成本的 `estimated` 标记，省略凭证、完整模型参数快照和服务器内部文件路径。导出用于审阅，不能代替数据库及制品的完整备份。

## 数据门槛

自动采集仅覆盖实验内证券，复用 baostock 原始日线、财报和分红资料，不修改观察池。回补资料只能在真实采集时间之后参与前瞻决策，不能为过去日期补造当时可见的数据。

普通行情没有完整的逐日交易规则和公司行动证明，因此“采集完成”不等于“可以模拟成交”。每个证券交易日还需要经核对的执行证据：上市日期、主板普通股资格、是否为普通涨跌幅限制交易日、ST 状态、参考价和合法上下限、价格最小单位、交易单位、规则版本与来源、公司行动覆盖情况及资料时间。页面的证据导入使用 `POST /api/simulations/{id}/execution-evidence`；录入人需对证据负责，服务不会把输入标志当作交易所认证。

证据必须来自可核对的原始来源，不能直接用“昨收 × 90%/110%”填补缺口。未覆盖的上市特殊期、未知规则、缺失的公司行动或冲突的证券状态会阻塞。成交前若发现未处理公司行动，应先补齐公司行动和权益证据，再恢复结算。公司行动通过受认证的 `POST /api/simulations/{id}/participants/{participant_id}/corporate-actions` 单独入账，当前没有公司行动表单。现金分红登记要求提供 `entitlement_date`、有限正数 `cash_per_share`（本实验税费假设下的每股净现金）和唯一权益引用；服务按登记日收盘前账本数量核对 `amount`，统一按分四舍五入（HALF_UP），登记日之后已卖出的原有持仓仍有权益。到账事件按同一账户、证券和权益引用核销，不能跨权益挪用应收或重复登记。拆股若已跨过后续成交、需要重放历史才能正确处理，会明确阻塞。不能安全处理的公司行动明确阻塞。公司行动与未释放订单预留冲突、或需要修正既有成交时，补录证据不保证自动解锁；当前没有通用历史重放或手动重解释订单的入口，需保留异常与原始记录。

冻结订单使用观察日已知的交易单位、tick 和历史成交额，不要求提前取得下一执行日的价格上下限；执行日证据在收盘确认时再核验。明确停牌且成交量为零的证券，缺失成交额按零容量处理，允许其他股票与主动持有继续；该证券的正数量新订单仍被容量检查拒绝。活跃证券缺成交额不会按零补齐。

`GET /api/simulations/{id}/availability` 返回证券和日期的数据缺口；默认检查当前上海日期，休市日会明确标记。它是就绪诊断，具体轮次还要通过冻结资料、预算、时钟、账户 revision 和未完成结算检查。

## 每轮如何执行

scheduler 启动及约每 60 秒检查可推进实验；worker 按真实上海时钟处理，收盘后从 15:05 起准备当日观察轮，截止为下一已核验交易日 09:00。固定窗口已经错过时不补历史决策。盘前／休市日手动刷新只采集最近已结束的交易日资料，不提前生成当日收盘数据。

- 收盘后采集并冻结共同资料，当前历史价格窗口固定为最近 60 个自然日。每个 Agent 获得同一资料包、自己的账户和已结算历史；只有冻结记忆策略允许时才附加可用的成熟复盘。
- 决策截止时间固定在下一交易日开盘之前。模型只能输出持有或带固定数量和保护价的订单意图；代码校验资金、持仓、交易单位、限额和 T+1，再冻结订单。
- 下一交易日完整日线和可信规则到齐后，`daily_open_v1` 用开盘价及预设不利滑点模拟一次执行机会。跳空越过保护价、停牌、容量不足或规则不允许时不成交。首版整单成交或不成交，不模拟部分成交、集合竞价排队或盘中触价。
- 成交、费用、权益和净值由确定性代码计算。模型无法写入实际收益或真实组合账户。缺资料的订单等待确认；错过决策窗口不回溯补单。
- 持有观察窗口结束且有完整净值后，生成复盘；模型复盘与确定性结果分别记录。只有达到成熟条件的本人复盘可进入后续记忆。价格上涨或下跌本身不自动证明投资逻辑正确或错误。

排行榜使用共同估值日期的完整净值，当前至少需要两个共同观察点，按累计净收益率排序并展示最大回撤。这是系统的最低展示门槛，不代表已经具备统计显著性。交易费率、费用下限和滑点是用户冻结的实验假设，不代表系统已自动验证当期适用费率；它们计入交易结果。模型服务成本另列，不从虚拟现金扣减。

## 预算与故障恢复

预算按参赛者、轮次和整个赛季限制 USD 成本及调用次数。每次真实请求（包括结构化输出修复）发送前都持久化预留；模型响应等待期间不持有业务写事务。可配置输入和输出每百万 token 单价；缺少价格时保留保守预留值，页面标注估算，不能当作供应商账单。

发送后结果不明确的调用保留成本占用并记录未知状态，不自动重跑以选择更有利的输出。预算不足、模型配置变化、超时、格式失败、错过截止和主动持有分别记录。实际使用量超过预留时按返回 token 用量及配置单价计算的金额记录，并停止后续调用，不把成本改写成预算内数值。即使 `estimated=false`，金额仍来自所配单价而非供应商账单核销；`returned_model` 没有取得时为空。

队列恢复依赖确定性的业务键、追加账本和 revision 核验：重复任务不重复成交；无法确定的模型调用不承诺恰好一次。修复资料后可再次推进轮次，旧证据与结果保留。所有 HTTP 写请求都要幂等键（`Idempotency-Key` 请求头或正文 `idempotency_key`，两处同时传入时必须一致）；生命周期请求还需要 `expected_revision`，同一动作的网络重试应复用同一个键和请求正文。

## 运维和验证

数据库备份同时保留 `data/simulation-runs/objects/` 内容寻址制品、现有 Agent 审计所依赖的制品和运行时交易日历。实验创建时还会把当时的日历及摘要写入数据库；历史读取使用归档日历，当前日历若改变赛季内交易日则阻止新的业务推进，单纯增加赛季外年份不影响历史读取。缺失或摘要不一致的原始制品会阻塞重建，不能仅恢复数据库后宣称资料完整。

本地离线验证使用项目 Python，避免虚拟环境 console script 的旧绝对路径：

```bash
.venv/bin/python -m pytest -q tests/simulation
.venv/bin/python -m ruff check src/investment_agent/simulation tests/simulation
# 真实浏览器回归需在获得执行许可、具备 Playwright/Chromium 的环境中另行运行：
# tests/browser/run.sh simulations.mjs
```

Python 测试使用隔离数据库、合成行情和假模型，不需要真实付费调用。浏览器脚本也使用隔离合成服务，但本次 Chromium 沙箱启动失败，随后提权请求被用户拒绝，因此桌面／手机真实浏览器验收未通过；HTTP、模板、CSP 和 Node.js 检查不能替代视觉与交互验收。最终统一回归结果以实施任务中的主调度记录为准。当前实现不包含分钟／tick 撮合、杠杆和做空、自动实盘下单、历史回放成绩排行，以及任意第三方投研工具访问。上述能力需要独立数据和规则验证后再扩展。

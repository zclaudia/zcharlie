## 2 原件归档契约要求

- 保持 `DatasetDraft`、旧单文件 `raw_ref` 和已存资料内容不变。新采集记录独立关联资料版本，不能向旧不可变行补写归档引用。
- 归档按来源及受控身份组织。每个正文保存名称、脱敏定位、媒体类型、HTTP 状态、原抓取时间（未知为 null）、SHA-256、字节数与包内相对路径，清单有显式格式版本。
- 清单携带受控身份快照、来源、适配器版本、实际采集时间、请求窗口及预期文件名、缺失或解析问题，能够在没有原调研目录的情况下找到全部输入。
- 文件先原子写入再提交数据库引用。清单和正文都校验，拒绝越界路径、符号链接逃逸及敏感请求信息泄漏。原件正文自身按来源保留，不将其作为可执行指令。
- 同一材料重复导入复用资料及原件；新抓取时间可形成新的采集记录，但不制造新的财务版本。完全无新资料或部分失败也保留独立采集依据。
- 旧库升级不改旧资料；新采集记录具备 ORM 与 SQLite UPDATE、DELETE、REPLACE 防护。没有归档的旧资料继续可读并显式标记归档缺口。
- 重放只使用归档内容，不请求网络或搜索旧目录；验证当前适配器版本匹配，尊重原抓取时间未知与 HTTP 失败语义。失败原件可验证和查看，但不能被当作有效财报。

## 3 验收用例

1. 港股三表和 SEC 主文件及动态发现历史分片全部入包，并关联年度资料与申报索引版本。
2. 同内容重复导入幂等；只有抓取时间变化产生新采集记录、财务版本不变；内容修订新增版本，旧引用不变。
3. 数据库和归档复制到新目录，原输入目录移走且网络调用被禁止，重放得到相同事实和确定性指标。
4. 缺失正文、字节或哈希不符、清单被改、非 2xx、未知抓取时间、部分失败都有明确结果。
5. 无草稿或取数中途失败时已收到的正文仍归档；进程或写盘失败不会提交指向缺失正文的已完成采集。
6. 旧单文件 `raw_ref` 可读；旧库迁移后资料行不变；ORM 与直接 SQL 不可改删替换采集记录。
7. 路径穿越、符号链接、请求 URL 中的凭据和密钥查询参数不进入可公开的归档定位。
8. 原件包与数据库一起备份恢复；财务 GET 仍只读；默认在线刷新与行情估值分红能力位保持关闭。

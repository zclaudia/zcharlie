## 3 任务交付与验收标准

### HK2-01 能力与来源验收矩阵

交付每个来源及能力的范围、身份绑定、使用限制、核对依据、验收状态、缺口和启用条件。分别记录存储、解析、计算、API、页面、在线采集的状态，修正“算法已有”被写成“产品已可用”的描述。

验收标准：

- 八家身份与实际来源逐一对应；SEC 财报、港股三表、行情、汇率、分红独立列项。
- 年度 PE 与分红明确记为计算或解析函数已有、当前默认读模型和页面尚未接通；不再笼统标为全部可用。
- `financials`、`price`、`annual_pe`、`dividends`、`pb`、`online_refresh` 各有明确判定条件；区分来源已允许使用与当前证券具备足够数据。
- `README`、产品说明与新验收记录一致，首期历史测试记录保留日期，不覆盖为新结果。

涉及：`docs/product/hk-us-expansion.md`、本目录验收文档、`materials/context.py` 中能力定义的设计说明。

### HK2-02 多响应原件归档与重放

交付可持久化的原件包及版本化清单，覆盖港股三表、SEC CompanyFacts、Submissions 和索引引用的历史分片。清单关联资料版本与各响应正文，单文件 `raw_ref` 继续兼容。采集发生但没有生成新资料版本时，也保留独立采集记录与原件引用。

验收标准：

- 每个响应记录来源、脱敏后的请求定位、HTTP 状态、真实抓取时间、正文 SHA-256、字节数及包内相对路径；未知旧时间保持未知。
- 将数据库与原件包复制到新临时目录，移除原调研目录并断网后，仍能重放得到相同事实及确定性指标；不要求新的导入时间与旧值相同。
- 缺片、正文损坏、哈希不符、失败 HTTP 响应明确报告；没有原件的旧版本继续可读并显示归档缺口，不伪造原件。
- 重复归档与导入幂等；抓取时间更新不制造财务事实变更。正文先原子落盘再提交数据库引用，故障重试不留下指向缺失正文的已完成资料。
- 修订产生新版本，旧版本与研究引用不变；迁移保留旧行并继续满足不可变保护，原件包纳入备份恢复范围。

涉及：`materials/store.py`、`offline_import.py`、`handlers.py`、资料仓储与模型；需要新表或列时新增迁移，不改历史迁移。

### HK2-03 指标自动进入研究发布

交付从 `compute_metrics` 结果到证据与 `save_material_calculation` 的应用服务，复用同一套计算规则。页面 GET 保持只读，计算记录持久化由显式研究或发布准备动作触发。

验收标准：

- 六项指标逐一映射输入事实、精确资料版本、报告期、方法版本、单位与币种；同一年度多来源冲突不能靠 `metric@period_end` 自动任选一个输入。
- 每项指标至少一个适用样本从资料导入、自动计算、记录保存走到发布数字校验，测试不手工重算结果代替服务调用。
- 缺失、冲突、不适用或公布时间不足以支持指定时点的结果，不生成可发布的数值记录，返回可定位的原因；不通过回填时间绕过证据可见性检查。
- 相同输入、方法版本与发布准备请求重复执行不产生重复计算；结果与页面数值一致。
- 新资料版本使新计算绑定新输入，历史发布仍解析旧引用；无引用数字与未经支持的跨币种发布仍拒绝。

涉及：`materials/metrics.py`、`metric_core.py`、`evidence.py`、`investor_bridge.py` 及研究应用服务。

### HK2-04 最新年度与缺片补验

交付八家公司按实际验收日期确定的最新已发布完整年度清单、年度事实与发行人原件对照表。补全所选 SEC 索引窗口引用的历史分片，明确窗口外材料不属于本次覆盖。

验收标准：

- 8/8 公司都有最新年度核对结论，包含实际财年起止、申报或公布日、原件定位及核对日期；年度来自实际披露，不固定写 2024、2025 或自然年。
- 每家公司至少核对收入、利润、资产、权益、经营现金流、资本开支六类输入；具体利润归属与口径写明。不适用或原件未单列时逐项解释，不为凑数填值。
- 需要同比与三年 CAGR 的公司具有最新四个连续完整财年；平均权益 ROE 补齐所计算年度的期初权益。缺历史输入时相应指标明确不可算。
- 重点案例涵盖汇丰 HKD 报价与 USD 报表、腾讯资本开支定义、AAPL/COST 52/53 周、JPM 银行口径、TSM ADS 与 TWD 报表及其口径冲突。
- 所选来源窗口的缺片清零，或明确列为资料不完整。导入退出码 2 不能标成完整通过；若某家外部证据不可得，登记阻塞并缩小发布范围，不能宣布八家全部验收。
- 单独记录逐字段核对覆盖；“最新年度已核对”不扩大为“全部历史字段均已核对”。

涉及：受控名单证据注记、适配器映射、裁剪后的 fixtures、新的年度验收报告。大体积原件保存到 02 的归档位置。

### HK2-05 按来源控制在线刷新

交付按来源和受控证券范围判定的刷新策略，替代单一全局布尔值作为唯一开关。默认关闭；来源使用范围通过核对后，仍须完成 06 才能进入日常启用状态。

验收标准：

- 可以先启用通过验收的 SEC 财报来源，港股来源保持关闭；一个来源失败不阻断其它已允许来源。
- 源许可状态、技术验收状态、运维启停分开表达；普通设置不能把尚未验收来源变成已验收。关闭策略在每次实际请求前重新检查，排队任务不能绕过关闭。
- GET 不取数、不入队；POST 说明每个来源的接受或拒绝原因；worker 区分成功、部分成功、失败和未启用。
- 限速、超时、有限重试、429 的等待策略与实际用户代理可验证；401/403、结构错误和非法数据不无限重试。
- 同请求并发去重；进程中断可恢复，不重复保存版本；旧适配器版本任务按明确策略拒绝或重新入队。
- 港股显式期间请求可以准确执行，或在入队前返回不支持的原因，不等到执行后才发现请求无法满足。
- 如引入运行时配置，统一接入现有 settings 注册、校验与历史机制，避免环境变量、数据库设置及常量互相矛盾。

涉及：`materials/refresh.py`、`jobs.py`、`handlers.py`、`context.py`、API schemas、现有 settings 与任务运行详情。

### HK2-06 在线来源验收

交付按来源记录的真实抓取报告。验收仅覆盖实际调用过的来源与证券，状态逐项登记。

验收标准：

- 每个拟启用来源，在至少 3 个不同日期进行真实采集，覆盖该来源绑定的受控证券；记录请求数、成功与失败、耗时、限速和资料变化。
- 最终连续 3 次观测没有未解释的结构或字段漂移；失败修复后重新累计。该门槛只支持受控试运行，不宣称长期可用率。
- 新取得年度与 04 的已核对资料一致；合法修订形成新版本并保留差异依据；相同内容不重复产生资料版本。
- 多响应全部可归档、断网重放；线上实际失败如实记录，429、超时、部分响应失败和 schema 改变另有可复现模拟测试。
- 实际演练关闭、在途停止、重启恢复、旧版本读取；来源关闭后没有新增上游请求。

网络用例显式使用 `network` 标记，与离线 CI 分离。某来源失败只阻塞该来源启用，不阻塞其它已通过来源与 M1。

### HK2-07 页面状态与浏览器验收

交付与实际数据一致的财务页、刷新结果和运行详情。财务能力存在不表示所有字段完整或最新，页面分别展示这几种状态。

验收标准：

- 页面可区分未覆盖、未采集、部分资料、资料过期、待原件核对、字段冲突及来源未启用；区分最近尝试、最近成功与最近原件核对时间。
- 新鲜度采用各公司实际披露及核对记录；失去新年度发现能力时显示“截至某日核对”，不推断当前仍是最新。
- 刷新从入队到运行、完成或失败的状态可追踪；入队、关闭来源或失败均不更新“最近成功采集时间”。
- 来源启用、当前证券数据覆盖和指标可计算性共同决定展示；不把全局能力位当作每家公司都有结果。
- 浏览器覆盖八家身份与币种展示，桌面和移动视口复核；针对空、部分、冲突、过期、关闭和失败状态保留截图及交互结果。
- M1 只开放已验收财务与指标；M2 再验收真实刷新交互，后续 10/11 完成时分别增加估值和分红区块。

涉及：`web/routes.py`、`stock.html`、`financials.js`、`materials/context.py` 及 Web 契约测试。

### HK2-08 回归与分阶段发布

交付新的验收矩阵、部署操作说明和按里程碑追加的完成记录。本计划授权范围为规划，实际实现时再执行数据库迁移、采集和部署操作。

验收标准：

- 新临时环境完成迁移、身份初始化、原件导入、财务页面读取、自动计算发布及重启后引用解析。
- 每个新增迁移有旧库升级、已有行及不可变保护回归；迁移前备份，演练数据库与原件包一起恢复。
- 定向用例、全量离线 pytest、ruff、mypy 通过；若开工基线已有失败，逐条附独立复现，不以失败总数相同替代回归判断。
- 既有 A 股 golden fixtures 与评分结果不变；离线测试没有真实上游访问，财务 GET 不出现写操作。
- M2 在上述基础上增加 06 的来源报告、启用与回退操作；关闭网络后仍可阅读已保存资料。
- 发布记录区分代码已合入、数据库已迁移、资料已导入、来源已启用四个状态，不能用测试数据库结果代表应用环境已就绪。

### HK2-09 日行情与汇率

交付日收盘价和有日期的汇率资料，按来源独立核对使用范围与稳定性。复用归档与版本机制，不在财务 GET 中临时请求上游。

验收标准：

- 行情包含证券、交易所、交易日期、时区、币种、调整方式及来源；休市、停牌和陈旧报价保持可区分，不伪造成当日新价。
- AAPL 拆股案例证明历史价格与 EPS 的每股基础一致；只有一个已验证来源时披露覆盖限制，不宣称已交叉验证。
- 汇率含币对、方向、单位、日期及来源，以已知金额做双向换算测试；沿用或显式修订现有估值模块的 3 日最大滞后规则，不无限沿用旧汇率。
- 汇丰 HKD/USD、腾讯 HKD/CNY、TSM USD/TWD 分别有案例；汇率缺失时保留原币，拒绝隐式换算。
- `price` 只在相应证券有合格行情时可用；估值结果另外检查 EPS 与汇率，不随价格位一起全开。

### HK2-10 年度 PE 产品接线

复用 `materials/valuation.py`，将计算结果接入读模型、API、页面及来源追踪，不重复实现算法。

验收标准：

- 正 EPS、亏损、缺 EPS、币种不同、汇率过期、拆股基础不同均有测试；基本与稀释 PE 分别命名，显示价格日及 EPS 对应完整财年。
- 收益、股数及证券类别匹配；TSM ADS 继续不适用，除非新增带原件、有效期和每股基础的比例转换验收，不能只凭名单中的比例开启。
- 页面与计算记录能追溯价格、EPS、汇率的精确版本；负 EPS 不显示为普通正向估值结果，缺输入返回原因。
- 年度 PE 按证券及输入资格判断，不联动开启 PB、TTM、历史分位或跨币种研究发布。

### HK2-11 分红事件与条件股息率

先交付已核对事件展示，再在覆盖和价格满足条件时交付指定口径的税前股息率。事件展示允许使用经过核对的离线材料，不强制依赖在线来源或行情。

验收标准：

- 事件持久化并接入读模型、API 和页面，区分普通与特别分红、每普通股与每 ADS，以及公告、除息、登记、支付和最终金额确定日。
- 汇丰案例中，2025-03-06 的已知金额不能使用 2025-04-14 才确定的 HKD 最终金额；未知公告日期保持未知。
- 只有部分事件时显示“已核对事件”及覆盖范围，不宣称完整分红历史，也不输出年度或滚动股息率。
- 股息率必须显式声明时间窗口、截至日期、是否含特别分红、价格日及币种；缺覆盖证明、价格或汇率时无值并说明原因。
- 税后到账、预扣税与 ADR 费用继续不计算；事件能力与股息率资格分别判定，不能复用一个开关表示两者均可用。

M1 完整退出要求八家全部满足验收。若港股来源或某家原件受外部条件阻塞，可以交付美股或其它已通过子集，但必须标为部分交付；M2 对该子集可以先行，不以等待全体为由停工，也不将部分结果写成八家全部完成。

M1 约 9–14 个有效工作日；M2 在其基础上约 4–7 个有效工作日，另需至少 3 个不同日期观测；M3 约 6–9 个有效工作日及来源等待。上述是容量估算，未设发布日期，任务之间可独立推进以减少等待。

## 5 开工与收口方式

1. 开工时记录实际 HEAD、工作区状态、当前迁移 head 及全量门禁，更新本计划基线；实际实现建议使用 `codex/` 分支和独立工作树保护主目录工作。
2. 先落实 01 的矩阵与 02 的归档契约，再实现 03。资料补验与在线路径按依赖推进，每个任务以可复现测试和制品收口。
3. 为下一阶段建立单独完成记录与验收报告，逐项记录代码位置、运行命令、结果、原件位置及未结条件；所有测试文件名称在实现时确定，不把计划条目当成已有测试。
4. 遇到来源外部阻塞时，继续推进离线导入、归档、指标接线、模拟故障与页面验收；该来源保持关闭。
5. M1、M2、M3 分别收口。部署时只执行对应已通过范围的迁移、导入与来源启用，保留回退说明。

原有资料契约、不可变版本、真实时间、原币与口径纪律继续适用。严格历史时点查询及全量不可依赖公告发现需要单独设计，不能由新增日期字段、版本存储或三天采集观测推导为已实现。

## 架构门禁审阅

主代理审查新增依赖后，抽取了 `AccountAssessmentRequest` 作为两类请求的共同契约，消除 `portfolio -> candidates` 的反向依赖。序列化字段与旧ag22契约不变。

导入图基线明确接受7条本功能所需的新包依赖：`candidates -> investor/jobs/portfolio/settings` 分别用于精确引用、既有队列、账户财务检查和运行时开关；`storage -> candidates/investor/portfolio` 仅用于不可变制品的领域DTO解析、精确引用与整份集合校验。持久化层不调用候选提名、账户事实写入、研究或正式发布服务。这是主代理对计划中typed repository边界的审阅结论，基线只增加这7条，不放宽门禁算法，也不隐藏函数内导入。

# wmshare 三项数据实验方案

日期：2026-11-12；2026-11-13 更新。状态：首轮真实实验部分完成，免费 EC 耗尽后停止。
真实结果与成本见[首轮实验报告](../review/wmshare-free-trial-2026-11-13.md)。
付费后已完成 20 股分红实验与筛选诊断，见[后续实验报告](../review/wmshare-paid-trial-2026-11-13.md)。

目标：用一次小规模真实取数，判断 wmshare 的全市场候选发现、行业估值背景、
高股息研究数据，是否值得接入 zcharlie。三项分别得出结论，可以只采用其中一项。

技术参考基线：wmshare `1.19.0`，仓库提交 `03bc249d9fd1d26e256a0dcfd5d9d72c2256c459`。
前期调研已通过目录、单位、批量与演示数据相关的 804 项离线测试；真实验证进度见首轮报告。

## 1. 实验方式

入口为 `tools/probe_wmshare.py`，实验环境固定安装基础 SDK `wmshare==1.19.0`。使用 SDK 自带的认证、
超时、重试和错误类型，按顺序取数，不引入通用 provider 框架或新的任务系统。
凭证使用 `WMSHARE_CLIENT_ID`、`WMSHARE_CLIENT_SECRET` 环境变量。

首轮在 A 股收盘并完成日终更新后执行，三个实验共用样本和响应。已有数据的对照
通过项目 repository/service 读取；没有本地数据的样本如实留空，不为实验回补全库。
本轮只保存实验文件，正式页面与数据库接入根据结果另做小改动。

安装可选实验依赖后执行（需要已有项目虚拟环境）：

```bash
uv pip install --python .venv/bin/python 'wmshare==1.19.0' matplotlib
export WMSHARE_CLIENT_ID='你的 AppId'
export WMSHARE_CLIENT_SECRET='你的 API Key'
.venv/bin/python tools/probe_wmshare.py \
  --database .dev/data/app.db \
  --output data/experiments/wmshare/live-01
```

`--database` 使用要对照的本地数据库路径，示例为开发库；省略时仍完成取数，池归属与本地
对照留空。当前本地对照目标池为 CSI300，观察池采用启用条目。脚本不自动读取项目 `.env`，
凭证需在执行命令的进程环境中设置。缺少凭证时直接提示变量名称，不创建实验结果。

取得凭证后即可开始。先完成一次取数和对照；
只有出现更新延迟、异常跳变等问题时，才对相关接口补跑后续交易日。

## 2. 共用样本与记录

固定 12 只 A 股，覆盖银行、消费、公用事业、资源、制造和科技：

`600036.SH`、`601398.SH`、`601288.SH`、`600519.SH`、`000858.SZ`、`600900.SH`、
`601088.SH`、`600028.SH`、`300750.SZ`、`002415.SZ`、`688111.SH`、`600029.SH`。

再从实验一的两份结果中交替补入 8 只不同股票，尽量选择现有目标池以外的标的，
构成 20 只研究样本；不足 8 只时使用实际数量。全市场筛选结果仍保留各自前 50 行，
20 只只是详细对照的上限。

每次调用记录接口、参数、抓取时间、耗时、成功/失败和 SDK 返回的 EC 消耗。
保存 SDK 返回结果，并保留可取得的服务端日期；缺少数据日期时明确标成未知。
EC 未回传记为未知，不计作零。凭证不进入文件。上述记录只用于复现本次实验，
不扩建生产审计系统。

## 3. 实验一：全市场候选发现

**要回答的问题：相对于现有目标池，能否低成本找到值得继续研究的新公司？**

通过 `cli.screener.query()` 跑两条固定条件。阈值只用于检验数据与发现能力，
不在本轮调参，也不据此判断收益表现。

| 查询 | 条件 | 排序 |
|---|---|---|
| 盈利与现金流 | `$ROE_TTM_LAST > 0.15 && $NCFO_NP > 1 && !$IS_ST && !$IS_SUSPEND` | ROE 降序 |
| 较低历史估值 | `$PE_TTM_LAST > 0 && $PCT_PE_TTM_10Y_LAST < 0.3 && $ROE_TTM_LAST > 0.08 && !$IS_ST && !$IS_SUSPEND` | PE 十年分位升序 |

每条取前 50 行，同时返回筛选用到的指标及 `$INDUSTRY_CUR`、`$MV_LAST`。
显式传入 `fields` 时包含全部筛选字段，方便核对命中理由。
保存服务端 `count` 和实际返回行数；前 50 行只用于审阅，不称为完整命中名单。

使用证券目录核对标的类别，剔除 B 股、基金等非 A 股证券。`market="cn"`
本身不作为 A 股类别保证；报告同时列服务端命中数和前 50 行中的有效 A 股数。

对结果增加“在目标池 / 在观察池 / 新发现”三列。详细样本再用
`cli.indicator.metrics()` 取同名指标，与筛选行逐项比较；本地已有财务数据时并列
显示，但年度 ROE 与 TTM ROE 分开标注，不计算两者的数值误差。

**交付：** 两份筛选结果，以及最多 8 只新发现公司的简表，写出行业、命中条件、
当前池归属和下一步值得研究的问题。

**采用依据：** 筛选行能支持所写条件、与单股查询基本一致，并能提供现有池外有意义
的研究线索。若只有熟悉的大盘股或缺失字段过多，就降低这项的接入优先级。
若有用，优先接到现有候选发现流程，沿用后续研究入口和去重逻辑。

## 4. 实验二：行业估值背景

**要回答的问题：能否让股票研究多一层“所在行业当前处于什么估值位置”的背景？**

用 `cli.index.universe_keys(group="industry")` 和 `cli.stocks.industries(level=1)` 获取行业键与名称，选择银行、
食品饮料、公用事业、电子四个申万一级行业，再加沪深 300 基准。键从返回目录选择，
不在脚本中猜造。行业分类不细到白酒，避免把一级行业与我们已有白酒同业组混为一谈。

对五个对象调用 `cli.index.trend(key, window="5y")`，一次取回历史点与可用的
3/5/10 年分位。重点整理：最新日期、PE、PB、五年分位、历史覆盖及缺失原因。
银行以 PB 为主要观察列，其余行业同时展示 PE/PB。

从返回序列按供应商定义复算五年分位，核对接口值和窗口；不另拉全行业成分股重建
整体法估值。保留接口返回的缺失值，不为凑表另造替代数值。

**交付：** 一张五行的估值背景表，配一张五年趋势图。为 20 只样本中可映射到这四个
行业的股票补充对应背景；其余样本本轮不扩行业覆盖。

**采用依据：** 数据日期与更新频率清楚、序列可用、分位可从同一序列解释，且能给
研究提供额外背景。若有用，先在行业页或股票页增加一块估值背景展示。
供应商的行业整体法分位与我们已有个股五年分位各自保留名称和口径。

## 5. 实验三：高股息研究

**要回答的问题：能否比现有 TTM 股息率多回答“分红是否持续、派息是否有压力”？**

对共用样本取以下数据：

| 数据 | 接口 | 用途 |
|---|---|---|
| TTM 股息率、TTM 派息率 | `cli.dividend.snapshot(symbol)` | 当前收益率和盈利覆盖 |
| 最近五年分红事件 | `cli.dividend.history(symbol, begin=..., end=...)` | 分红连续性及每年每股分红 |
| 三年股息率均值、ROE TTM、经营现金流/净利润 | `cli.indicator.metrics(symbol, codes)` | 长短期收益率和派息支撑背景 |
| 最近收盘价与日期 | `cli.kline.last(symbol)` | 对齐股息率比较的价格日期 |

三年均值使用 `$BONUS_RATE_3Y_AVG_LAST`；后两项复用实验一的单股指标请求。
实现时先核对 `snapshot` 的实际字段，若缺少两项 TTM 数值，再补调对应的
`yield_ttm()` / `payout_ttm()`，不重复请求已有数据。

历史查询使用截至取数日的最近 1825 天，遵循 SDK 区间上限；首尾不足整年的列标明覆盖期。
从事件中按除权日统计已实施现金分红，列出各年每股分红和最近 365 天合计。
用相同日期的价格对照本地 `dividend_yield_ttm`；样本不足五年时展示实际年份。
预案单独列示，不加入已实施金额。跨拆股、送转的每股数值变化标明事件，
本轮不开发通用公司行动复权模块。

对股息率最高的 5 只样本详细检查差异：日期、税前税后、预案/实施和价格口径。
差异超过 0.3 个百分点时展开说明；这只是排查阈值，不是一票否决标准。
分红明细里的派息率可能存在供应商已知回填滞后，使用 TTM 快照作当前派息率。

**交付：** 一张 20 只以内的分红对照表，包含 TTM 股息率、三年均值、TTM 派息率、
各年 DPS、现金流覆盖及本地差异。对最高股息的 5 只写简短判断，区分高且持续、
一次性分红抬高、利润覆盖偏弱和资料不足，并列出依据；不套供应商单一质量布尔值。

**采用依据：** 核心数值与事件能够解释，且连续性、派息率或现金流覆盖至少有一项
提供了现有页面没有的信息。若有用，优先扩展股票页已有分红研究内容。

## 6. 最小实现与结果

实现集中在一个脚本：建客户端 → 获取目录和筛选结果 → 确定样本 → 采集行业与分红
数据 → 读取本地对照 → 输出报告。三个实验各自返回结果；某项失败时继续其他项，
最后在报告中列错误即可。

预计首轮约 110–150 次 SDK 数据调用，实际请求和 EC 消耗以运行记录为准。
分红历史另外读取近期未截日期的记录以保留无除权日的预案；快照缺字段时补调两项 TTM 接口。
单股多指标合并取数，行业数据直接使用服务端序列。首轮结束再按真实消耗估算
每周发现、每日行业背景、每周分红更新的成本，不先做预算平台。

输出到指定目录：

```text
raw/                    每次 SDK 调用的参数、结果与调用记录
run.json                运行日期、SDK 版本、数据模式与本地对照快照
discovery.csv           两组筛选结果、池归属和命中指标
industry.csv            五个对象的估值背景
industry-trend.png      五年估值趋势
dividends.csv           共用样本的分红对照
summary.md              三项价值判断、差异说明、成本与建议接入位置
```

测试只覆盖实际需要的转换：筛选结果与目录类别匹配、行业序列的日期顺序和分位复算、
分红事件的日期窗口与已实施口径。使用少量保存响应即可，不重测 SDK 的认证和重试。

报告逐项给出“值得接入 / 补查一个具体问题 / 暂不采用”，附代表性样本。
一次性实验的结论是数据能否帮助研究，不宣称长期稳定性或策略收益。

### 离线回放与验证

```bash
.venv/bin/python tools/probe_wmshare.py \
  --replay data/experiments/wmshare/live-01 \
  --output data/experiments/wmshare/replay-01

.venv/bin/python -m pytest -q \
  tests/unit/test_probe_wmshare.py tests/unit/test_probe_wmshare_local.py
```

回放直接读取保存的调用结果，沿用原取数窗口和本地对照快照，无需凭证，也不调用 SDK。
输出目录应为空，避免覆盖已有实验。回放中展示的 EC 属于原始调用，不是本次计费。
`--as-of` 控制分红事件统计窗口；筛选、指标及价格接口始终是抓取时的最新值，不提供历史重建。

已验证：三项采集与 CSV 输出、行业分位复算、B 股/ETF 排除、预案和缺失金额处理、
部分接口失败、记录回放、本地只读查询及未采集与零分红的区别。测试使用合成 SDK 响应，
报告明确标记来源模式，不能据此评价真实数据价值。11 月 12 日离线阶段未配置凭证，未发起真实请求。

本次实现验证结果：17 项测试通过，Ruff 检查通过。开发库只读对照已跑通，离线演练为
20 只样本、111 条模拟调用记录；报告与图表位于
`data/experiments/wmshare/offline-verified-20261112/`（本机文件，未纳入版本库）。
本地 `.venv` 已安装基础 SDK 和 matplotlib。认证失败或额度耗尽后结束后续网络调用，
已获得的实验结果仍保存；其他单项错误继续列入报告。

### 2026-11-13 真实实验更新

已加载本地凭证执行，成功调用已知消耗合计 514,900 EC；条件筛选遇到 `POLICY_DENIED`，
取得银行和食品饮料两条估值序列后，公用事业调用返回 `EC_BALANCE_EXHAUSTED`，分红尚未取数。
当前额度不够跑完原方案，不再按调用次数推断免费试用是否足够。

脚本现将接口策略拒绝与凭证失效区分，策略拒绝只停止同一接口；新增 `--resume <旧结果目录>`，
用于下一次明确执行时复用成功记录并重试未完成调用。纯离线回放仍使用 `--replay`。
下一轮优先复用目录、先试 2–3 只分红样本，不重复拉全市场目录或五条历史序列。
此次修正后的 21 项回归测试与 Ruff 检查均通过，真实结果已完成零网络回放。

### 付费后补验

20 股分红的 100 次调用全部成功，已回传 135,845 EC；19 只有正现金事件，7 只平台 TTM
与除权日滚动现金累计不同。明确区分快照 quote_date、未确认实施记录及已实施现金口径。
充值后的官方最简筛选仍被 `POLICY_DENIED: assign` 拒绝，未绕过策略或逐股扫描全市场。

脚本支持 `--experiments dividends --samples <证券列表>`，可单独运行分红实验；
`--retry-policy` 仅用于用户明确要求、权限或账户状态变化后的诊断，默认不重试旧策略拒绝。
付费结果分析使用零网络回放；`--replay` 会沿用已保存的实验范围和样本。

# wmshare 分红接入方案

日期：2026-11-13。状态：已实现、生产迁移至 068 并启用观察池采集。
任务 #805 完成 9 股真实采集，消耗 22,769 EC；详见 [生产验收记录](../review/wmshare-dividend-live-2026-11-13.md)。
隔离验收及通用启用步骤见 [接入验收记录](../review/wmshare-dividend-integration-2026-11-13.md)。

目标：将 wmshare 的分红事件用于现有现金股息计算；平台 TTM 和派息率作为独立参考展示。
首期覆盖启用的 A 股观察池，复用现有 worker、周频调度、股票页和快照保存方式。
全市场筛选搁置，不继续诊断、不加替代扫描；本期也不扩展港美分红。

实测依据：[付费后实验](../review/wmshare-paid-trial-2026-11-13.md)。20 股分红的 100 次调用
全部成功，已回传 135,845 EC；7 股的平台 TTM 与除权日滚动现金累计不同。

## 1. 产品表现

股票页增加一块“分红”内容，使用现有卡片和表格样式：

| 区域 | 展示内容 | 数值来源 |
|---|---|---|
| 现金股息 | 最近 365 天现金股息率、累计每股现金分红、计算日与价格日期 | 本 app 的 `dividend_yield_ttm` |
| 分红记录 | 除权日、每股税前现金、派息日、来源；可展开年度明细 | 已保存的分红事件 |
| 平台参考 | “wmshare 平台 TTM 股息率”“wmshare 平台 TTM 派息率”、平台行情日期与抓取时间 | `dividend.snapshot` 原值 |
| 待确认记录 | 有分红金额但没有可信除权日的记录，列金额与公告日 | 原始历史中的未确认项 |

平台参考区域加一句：“平台口径，可能与按除权日累计的现金股息不同。”
日期相同且差异超过 0.3 个百分点时，显示“口径差异”及两个数值；不合并成一个数。
派息率超过 100% 照实展示，不直接生成风险结论。未采到、无有效记录和数值为零分别显示。

平台参考值不写入现有评分因子或规则字段。它们可以被查看，但不会替换现金股息率。

## 2. 现金股息沿用现有算法

直接调用 `factors/library.py::_dividend_yield_ttm`，不另写一套计算：

```text
窗口：(as_of − 365 天, as_of]
现金股息率 = 窗口内每股税前现金分红之和（按现有送转规则调整）
             ÷ as_of 当时可用的最新不复权收盘价
```

- 以真实除权除息日决定是否进入窗口，保持左开右闭。派息日作明细展示，不改为到账日口径。
- 保留现有送股、转增后的每股现金调整，以及价格和分红资料过期标记。
- 沿用现有行情来源，不为这项功能另取 wmshare 行情。价格较旧时展示实际日期与质量标记。
- 覆盖不足仍返回缺失；已有完整覆盖且没有现金分红时才能得到零。
- 新数据只影响之后的新计算；历史研究结果不重写。

### 事件来源的简单选择

对首期观察池，优先使用覆盖完整的 wmshare 现金事件；否则继续使用整段 baostock 历史。
一次计算只选择一个现金事件供应商，不把两家同一笔分红相加，也不逐条挑较大的金额。
选择结果和原因写入现有因子引用信息，页面显示实际来源。

观察池决定采集范围；读取历史时按当时已采到的数据和 `captured_at` 选择来源，
不依据今天是否还在观察池切换过去的来源。已保存研究仍读取当次计算与引用。

wmshare 没有可靠的数值型送转数据，**不能把缺失的送转比例变成 0**。
送转调整继续取现有 baostock 事件，只提供股本变动，不重复引入其现金金额。
两类数据按日期组装成现有 `DividendHistory`，使用原来的复权计算；同一天合为一个
`Dividend`（wmshare 现金＋baostock 送转乘数），保留只有送转而没有现金的日期，
不能简单拼接两个列表。引用中保留现金与送转的来源。
baostock 送转资料不覆盖所需窗口时，回到原有 baostock 整段计算及原有缺失/过期处理。
完整年份采集记录不单独作为“送转为零”的证据；有送转迹象但数值无法解析的情况，
保留缺口并走原有路径，不为启用 wmshare 而填零。送转能力限于现有实现支持的范围。

因此首期仍保留观察池对应的 baostock 分红采集。wmshare 补充现金事件与平台参考值，
不承担它未提供的公司行动能力，也不新增公司行动处理框架。

## 3. 每股只取两个接口

每周随现有分红调度，对启用观察池逐股取：

1. `cli.dividend.history(symbol, limit=500)`：保留原始、未按日期截断的返回，
   本地划分事件年份与待确认项。
2. `cli.dividend.snapshot(sym=symbol)`：保存平台 TTM、派息率及其 `quote_date`。

第一次可保存已返回的更早明细；正常计算只要求最近 365 天涉及的年份。
未截日期的请求能保留待确认分红，也能在过滤前发现返回数量达到上限的情况。
不再重复取“区间历史＋近期历史”，不请求全市场目录、单股指标或另一份最新价格。
股票代码、名称与范围直接使用本地 listing 和观察池。

页面提供一个“刷新分红”动作，仍入现有队列。认证失败或额度耗尽停止剩余标的；
个别股票失败按现有任务方式记录，已保存的数据照常可读并显示时间。
EC 记录在本次任务 metadata 中，不新增预算服务或付费管理页面。

按本轮“区间历史使用同样 500 条底层查询＋快照”的消耗估计，20 股一轮约 10 万 EC；
实际以任务回传计量为准。首期按周更新即可。

## 4. 事件解析与覆盖

| wmshare 字段 | 处理 |
|---|---|
| `ex_div` | 真实除权日；有值且不晚于计算日才进入现金累计 |
| `ex_date` | 只保留原值，不能替代缺失的 `ex_div`；实测可能回填成公告日期 |
| `dps` | 每股税前现金金额，用 Decimal 入库，不从文本推算“每 10 股” |
| `announce`、`pay` | 公告日、派息日；保留未知日期，不补造 |
| `sas` | 原始财报期标签，只用于明细说明，不决定现金窗口 |
| `content` 等 | 随原始记录保存；没有可信数值时不推算送转比例 |

正金额但 `ex_div` 缺失的行，以及未来除权的行，保存为待确认/待实施记录，不进入现金累计。
零 DPS 占位行不作为发生过现金分红的证据。完全重复行先去重；同除权日不同记录只有在
能确认是不同分红组成时才合并并保留明细，含义不明时记为未完整，不重复累计。

沿用 `dividend_coverage` 与 `dividend_coverage_check` 按供应商、年份记录覆盖。
必须先确认请求成功、未达到上限、字段可解析，再标记截至本次抓取时的覆盖；
只查询部分年份不能标成更长历史已齐。返回空列表时先记“无有效记录/覆盖待确认”，
不自动覆盖成“零股息”；计算可回退到已有 baostock 的完整覆盖。

实时采集使用真实 `captured_at`，不把新抓取的记录伪装成过去已经持有的数据。

## 5. 存储只做必要扩展

### 复用分红事件表，修正供应商隔离

`dividend_event` 已有 provider，直接保存 `wmshare` 事件；原始响应仍放现有任务制品目录。
需要一次迁移及对应 repository 修改：

- 唯一键改为 `(listing_id, provider, ex_date, version)`。
- `latest_events`、比较旧值和 `upsert_event` 均按 provider 查询；只改唯一键不够。
- 旧行 ID、来源和版本保持原样，不重算历史。

这是已有单供应商分红表扩到两家的必要改动，不新建通用供应商管理层。

### 新增一张平台分红快照表

`wmshare_dividend_snapshot` 保存 `listing_id`、`captured_at`、`quote_date`、平台
`yield_ttm`、`payout_ttm`、原始 payload 和 `raw_ref`。未确认事件可放在该次 payload 中。
每次成功采集留一份快照，页面读最新保存值；失败不清空上次成功值。
不把这两个平台指标塞进年度财务表，也不为待确认记录再建状态机或审批表。

事件、覆盖和平台快照按单股提交；允许仅一类数据成功，任务明确记录这一类缺口。

## 6. 现有代码接线

| 位置 | 最小修改 |
|---|---|
| `providers/wmshare_dividends.py`（新增） | SDK 客户端、事件/快照解析；同步 SDK 用 `asyncio.to_thread` 调用 |
| `snapshots/jobs.py`、`handlers.py`、`dividends.py` | 扩展现有 `dividend_snapshot` 对 wmshare 的分支，复用任务状态、制品、幂等和错误处理 |
| `scheduler/snapshot_jobs.py` | 同一周频调度增加观察池 wmshare 请求，并确保该范围的 baostock 送转资料继续采集 |
| `storage/models/pit_snapshot.py`、相关 repositories、Alembic | 供应商隔离和一张平台快照表 |
| `factors/view_db.py` | 选择现金事件来源、组装既有历史；保留所需送转资料与来源引用 |
| `factors/library.py`、`config/field_sources.yaml` | 算法不变；补充输入来源和此次实测口径记录，不全局替换 baostock 主来源 |
| 股票页读模型、`web/templates/stock.html`、对应样式/脚本 | 一个分红区域、事件表、平台参考值和刷新动作 |

股票页的现金股息读模型使用现有 A 股快照视图调用同一个因子。当前 iFinD observation 视图
没有分红历史，不直接拿它算该区域；复用可读取现有日线与分红的快照视图，不另写公式。

配置沿用项目的凭证与设置机制：wmshare 两个值作为 secret 设置，支持现有 `.env` 首次导入，
worker 读取同一配置；增加一个分红采集启用项即可。SDK 只安装基础包，不引入它的 MCP 依赖。

## 7. 实施与验收

按三个小批次完成：

1. 解析与存储：先用已保存的 20 股响应验证，完成供应商隔离和快照保存。
2. 采集与计算：接现有周任务，打通观察池现金事件到原有股息因子，核对来源与送转调整。
3. 股票页：展示事件、计算值和平台参考值，接单股刷新。

重点验证以下行为，不扩成通用数据平台测试：

- 招商银行按同日价格与已除权事件重算约 4.7291%，平台 2.3528% 另列。
- 中国银行、华电国际等无真实 `ex_div` 的正金额行，不误算成已经实施。
- 滚动窗口左边界、送转调整、缺价格/缺覆盖、零分红，继续通过现有因子测试。
- 两家同日同金额事件并存，重采幂等，不串版本、不重复累计。
- 同一天现金与送转合成单个因子输入，单独送转日保留，复权结果与既有算法一致。
- wmshare 不完整时走原有来源；送转资料未知时不默认乘数为 1。
- 平台快照及价格日期可见；任务失败或额度耗尽保留旧值并显示更新时间。
- 页面不混淆两种股息率，平台参考值不进入现有因子评分；历史研究结果仍可读。

完成标准是观察池内能刷新、能看到事件、现金股息由原算法得到、平台值独立展示。
本期交付不依赖全市场筛选接口恢复，也不需要新增筛选、通知或预算模块。

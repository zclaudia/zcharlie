现状与改动思路 /app/agent · 对话工作台

现在这个页面是把每个后端契约各配了一块表单：对象查找、范围下拉、重取收据、投资约定、记忆、档案控制、真实组合全堆在一张页面里，对话只占其中三分之一。重设计的原则：一件事一个位置——对话里只做对话（连同对象、任务、计划、意见卡片），档案放右侧抽屉，账户与约定这类“设置型”功能移到同页的二级页签。

位置现在重设计
选择对象输入框上方独立表单：先输入名称 → 点“查找对象” → 点结果 → 勾“添加为比较对象”；绑定状态是一行字“下一条：无证券绑定”对象是输入框里的芯片；输入 @ 或代码即弹出带消歧的候选；加第二个对象即自动识别为比较；发送后固定在那条消息上
处理方式“本次范围”7 项下拉（解释已有材料 / 局部核查 / 完整公司研究 / 组合建议…），用户要自己判断任务类型默认“自动”，输入框内一枚小胶囊；展开后是带一句话说明的单选，不满足前提的选项置灰并写明原因（如组合建议需先选账户快照）
任务进度所有任务面板堆在整串消息的最后面，与触发它的提问分离任务卡紧跟在触发它的回答之后：步骤、额度用量、取消入口都在原位；完整研究先出计划卡，确认后才开始
回答呈现纯文本；观点、证据、数字来源要去右栏找回答首屏 = 范围 + 立场 + 最重要理由 + 下一步；数字是带“事实/计算/假设”标注的节点；证据、反证、估值折叠；操作（我不同意 / 数据有误 / 记录决定）在回答下方
状态与错误一条 aria-live 文本“notice”承载所有状态；“重取待确认请求”“收据冲突”等工程概念直出状态就地显示：消息气泡下的“发送结果待确认”、顶部“依据的观点已有更新”条、任务卡里的“等你处理 / 正在停止 / 部分完成”。用词全部走契约里的文案映射
会话列表一串同样的按钮，标题默认“新对话”按“需要你处理 / 进行中 / 最近”分组；标题自动取“对象 + 首个问题”；带对象芯片与任务状态
右栏“研究对象与更新”里叠着档案视图、启用与约定、决定、记忆、档案控制；底部整宽“真实组合”右侧只放档案抽屉（判断 / 过程 / 决定，可收起）；“组合”“约定与记忆”“后台研究”各成同页二级页签，不再和对话抢空间
空状态标题“请选择或新建对话”，必须先点“新对话”才能输入直接可输入；给出按场景分组的示例问题，以及候选带入、待你处理的事项，并显示数据时效与已知缺口

保持不变的产品约束

  • 对象与版本在发送时固定；切换对象只影响下一条，历史消息不被追溯改变
  • 普通提问不会自动启动完整公司研究；完整研究先给计划，普通研究不逐步确认
  • 取消 = “正在停止”直到确认停下；断线重连只补进展，不取消任务
  • 发送未确认时不丢内容：草稿与原请求保留，只能重取同一份请求（幂等收据）
  • 引用的观点变化时：旧回答保持原样并标注“依据的观点已有更新”
  • 状态只用文字标签，颜色仅作辅助；枚举值一律用契约文案

有意识的取舍（待你拍板）

  • 档案抽屉默认展开，窄屏自动收起；是否默认收起可调
  • “处理方式”仍保留但降级为胶囊——想让它彻底消失（全靠自动）也可以，代价是用户失去强制“只解释已有材料”的手段
  • “组合 / 约定与记忆”做成同页页签而非独立路由，便于沿用现有 agent:* 事件与扩展挂载点；若想要独立 URL 也容易拆
  • 首屏不展示“模型指纹”“精确引用版本审计”等审计信息，移到各卡片的“详情”里

① 对话工作界面 桌面 · 进行中的会话（可点击右侧抽屉页签与“处理方式”）

三栏：会话 / 对话 / 档案。对象、处理方式、草稿状态都收进输入框；任务与计划紧跟在各自的回答之后。

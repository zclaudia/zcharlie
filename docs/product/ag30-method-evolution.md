提案来源为真实已结束 Task 的失败/部分完成过程复盘，冻结输入、授权、工具回执、进度、正式产物和精确引用。评估必须包含原失败、同范围成功反例、范围外成功反例，并对每案给出 expected pass/block 与真实硬门槛结果。fixture 检查证明工程控制，不证明语义研究质量。

离线影子使用实际 SDK FunctionModel 重放冻结输出，独立存储结果且没有正式发布、账本、持仓或通知副作用。它只是回归检查，不能满足批准门槛。前瞻影子适用于本卡的有限验证步骤：评估之后，用户通过既有对话主动启动真实新 Task，沿既有队列/预算执行；观察器冻结这些新输出，验证原方法通过而加强方法阻止的部分失败，以及加强方法通过的新成功反例。历史 Task 不能充当前瞻样本。观察器不额外调用模型、不写正式头。暂不支持需要新增研究工具调用的前瞻方法实验。

用户界面 `/app/methods` 显示变更摘要、适用 listing、评估、离线重放、前瞻结果、精确引用和历史。列表每类最多 20 条并明确分页，详情单独加载；大于 2,000,000 字符的原始产物拒绝内联。批准使用 auth+CSRF、完整冻结证据 hash、精确 proposal revision/scope、head CAS 和稳定 mutation UUID；模型不能批准。丢失响应后同 UUID/原 body 重试，不再推进头；401 保留待提交操作，409 刷新后需要用户重新决定。

每个 owner/listing 只有一个 active head。新 Task 在实际 admission 事务内冻结精确方法与配置；恢复/重试不跟随当前头。历史无 receipt Task 永久 baseline，旧序列化 grant/Task 的字节与指纹保持兼容。多 listing、组合、解释和比较使用明确记录的 baseline，不能混用方法。可信 publication 使用任务绑定的方法，客户端标签不能切换版本。当前权限、取消、归档、预算和授权仍实时检查。退役方法仍供既有任务和产物读取；回退追加新方法版本/事件，不删除历史，也不重写旧 Task、正式观点或持仓。

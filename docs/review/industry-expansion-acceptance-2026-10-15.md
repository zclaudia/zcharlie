# 行业分析扩展验收记录

日期：2026-10-15。执行计划：[行业分析扩展实施计划](../product/plans/industry-expansion/README.md)。三个 GPT-6 Luna 子代理分别实施指标内核、银行证据/导入、行业 API/页面；主代理独立审查、补充端到端测试并验收。

## 范围与当前结论

已实现白酒与银行两个显式版本指标集合、银行 FY2025 固定研究样本离线接入、可冻结的研究/Agent 引用、独立行业只读入口。银行交付的是**来源可追溯、缺口明确的候选数据版本**，不是四指标原件核验全部完成的银行研究产品。

银行 10 家供应商年度值保存为 candidate；净息差、不良贷款率、拨备覆盖率可生成描述性统计。年度加权 ROE 原始值虽有，但归母净资产未完成口径验证，因此不生成 ROE 比较。字段级银行原件 proof 输入与校验器未在本轮实现。已登记 PDF 不会自动提升字段核验状态。

本轮离线实现验收通过；全部测试分组三路复验共 3325 项通过、4 项跳过、6 项联网测试默认排除。生产库、生产开关、在线采集与真实外部 Agent 均不在本次启用范围。

## 独立复验结果

`tests/integration/test_industry_expansion_acceptance.py` 使用 tracked 白酒/银行固定证据、隔离 SQLite 和假模型，覆盖三条独立场景：

1. 双行业导入、银行重复导入、独立批次、HTTP 鉴权、四指标绑定、白酒基准、全名单统计、跨行业批次拒绝、候选输入的关键引用拒绝、篡改指标集合拒绝，以及 GET 不创建采集任务。
2. 应用正常准入、保存银行研究绑定、真实 worker 执行 FunctionModel 调用同行工具；工具输出与冻结计算引用相等，ROE 缺口及候选核验状态保持不变。
3. 导入已知供应商修订后，当前行业读取显示待复核状态和中文提示，继续展示原提交批次的旧数值；显式历史批次保持冻结语义，不混入后来输入。

使用本地完整 run-02 银行采集材料，在主代理新建的临时库另行执行真实离线导入/提交/读取，结果为 10 条年度快照、10 个目标、30 条已保存计算、10 项 ROE 缺口，批次状态 partial。工行三项结果如下，数值均为候选供应商事实形成的描述性比较：

| 指标 | 工行 | 其余 9 家中位数 | 有效同行 |
|---|---:|---:|---:|
| 净息差 | 1.28% | 1.74% | 9/9 |
| 不良贷款率 | 1.31% | 0.94% | 9/9 |
| 拨备覆盖率 | 213.60% | 313.62% | 9/9 |
| 加权 ROE 比较 | 缺口 | 缺口 | 0/9 |

银行全名单净息差中位数为 1.735%，页面按两位小数显示 1.74%；全名单与排除工行后的中位数虽显示相同，原始统计值不同。全名单拨备覆盖率中位数为 303.085%，不良贷款率中位数为 0.995%。

本地 3 份银行 PDF 中，工行和江苏银行两份通过原件身份/年度检查并登记；招行封面文字无法确认期别，未登记并返回明确原因。其他 7 家缺少本地原件。所有银行比率字段仍是 candidate，未升级为 verified。依赖这些未跟踪 PDF 的测试有明确原件 guard；跟踪的 48 KB 最小银行供应商 fixture 不依赖 PDF，包含来源响应 hash 和摘录 hash。

主代理还对上述银行实际临时库执行 `backup_research.py`、`verify_backup.py` 并恢复至另一临时目录：数据库和批次映射两个文件的清单校验通过；冻结 cutoff 下的银行读取结果、指标集合与计算引用恢复前后完全相等，数据库内两份原件 blob 的 SHA-256 均正确。

## 审查中发现并修复

- 旧批次新增默认指标集合字段会改变 hash：保留旧 JSON 形态及读写一致性，新批次显式绑定集合。
- 原件身份检查不能用公告标题代替 PDF 实际年期：撤回宽松回退，保持实际首页年度检查，仅增加明确标题/发行人别名，并限制页码不越界。
- 导入证明中的绝对路径会使复制目录产生假新版本：语义 hash 只保留稳定来源定位/内容和原件审查状态码。
- 新页面曾引用不存在的格式化导出：通过真实浏览器复验发现并修复，补充 ES 模块契约验证。
- 候选字段材料链接不能称为已核验原件；银行 ROE 缺口需中文解释；已修正页面文案与时间。
- 行业页用固定批次读取时会丢失当前来源更新提示：仅在当前名单、年度和批次均匹配时附加实时复核状态；历史读取不改变。
- 不支持的新版本计算记录不能使整个读取失败：查询侧跳过不可识别集合，显式计算与绑定仍拒绝未知集合。
- 页面快速切换时旧请求不得覆盖最新选择：请求序号限制显示，浏览器强制延迟白酒响应、先展示银行再释放旧响应，最终仍保持银行选择。10 个公司研究链接实际可读取，手机无页面级横向溢出。

| 命令（均附 `-q -p no:cacheprovider`） | 结果 | 耗时 |
|---|---|---|
| `pytest tests/unit` | 2008 passed，6 deselected | 360.19 秒 |
| `pytest tests/integration` | 600 passed，4 skipped | 400.78 秒 |
| `pytest tests --ignore=tests/unit --ignore=tests/integration` | 717 passed | 232.56 秒 |

各组独立覆盖 DATA_DIR、DATABASE_URL、API_KEY、LLM_TIER3_API_KEY，测试内部关闭 checkout 的 dotenv。4 项跳过均为 `test_gateway_contract.py`，需要外部已构建的 zclaudia-gateway 与 node；6 项联网测试按仓库默认规则排除。该门禁不代表银行在线接口、来源用途条件或真实 LLM 质量验收。

其他独立检查包括：双行业端到端 3 项通过；收尾后的银行/指标集合/行业 API 定向复验 19 项通过、23 项未选中；采集/审查回归与绑定合同等 32 项通过；银行导入/名单/白酒兼容及整链 46 项通过（这些组有重叠，不相加）；mypy 374 个源文件零错误；修改范围 Ruff、JS 模块解析和 diff whitespace 检查通过。

最后的等价原件读取调整（仅在封面身份未知时解析总页数，避免重复解析有效封面）与页面公司研究链接、请求显示保护，分别追加银行原件/白酒真实整链/JS 契约 16 项通过、JS 模块契约 14 项通过及真实浏览器复验；它们不计入上述分组总数。

## 使用与后续任务

在明确选定的隔离或目标环境中配置 `DATABASE_URL`/`DATA_DIR`，并先保证名单内精确证券身份已存在，再运行：

```sh
ia peers import-roster research/industry-data-validation/evidence/run-02/sample.json --industry bank
ia peer-annual import-bank --evidence-root research/industry-data-validation/evidence/run-02 --report-period 2025-12-31
ia peers submit-offline-batch --cohort-key bank_run02_sample --report-period 2025-12-31
```

银行默认名单键为 `bank_run02_sample`，可用 `--cohort-key` 显式命名其他研究样本。名单和年度导入本身不启动采集。打开 `industry_peer_context_enabled` 后可访问行业页面与只读 API；本次没有修改生产环境的开关或导入真实库。旧白酒命令与历史研究保留原有语义。银行在线采集在现有适配器未支持时明确拒绝。

后续按独立工作包补齐：银行合并归母净资产的字段映射与证明；银行字段级原件定位/当前列/单位及年度语义核验；其余原件取得；在线来源用途条件及银行年度适配器；真实外部 Agent 质量评阅。光伏需要单独口径验收，概念主题板块需要多重归属和名单历史设计。行业综合评分、轮动、历史可投资性回测不包含在本轮。

工作区另有其他任务并行维护的港美股文档、Docker 部署/存活探针、provider 修复等改动，本任务未回滚、提交或部署这些改动。全量门禁针对共享工作区执行，不能据此把其他任务的代码归为本任务交付。

# 研究事件机械交付

领域事件以调用方数据库 session 与原业务事实一起保存。事件不可修改或删除；消费者回执和扫描游标单独保存。扫描到某条事件不等于已完成业务交付，运行摘要必须同时看 retry、blocked、quarantined 和 last_success_at。

`worker-events` 专用进程只领取 `research_events_maintenance`。原 agent 与 collection 两组不领取该 kind；普通 `ia worker start` 默认也不领取它。显式配置必须只有此 kind，不能与研究或采集混用。该名称是实施时最终注册名，替代早期草案中的单数写法。

调度器的独立协程每 30 秒检查安装的机械消费者/唤醒回调，并尝试单活入队。它与原研究扫描的等待分离；无已安装消费者时不创建空任务。配置文件和注册测试已经覆盖这个边界，实际进程尚未在本轮启动。

每次 tick 的总预算为 50 条新事件、20 条重试和20条唤醒扩展动作；单个事件/效果片使用短事务。最多50个效果一片，所有效果完成才记 applied。投影、回执、游标及提交前租约栅栏必须同事务；失去租约不提交未完成的片。提交后失联依赖既有回执去重，不能重跑模型生成。

`run_maintenance_tick` 的协作执行预算为2秒，覆盖规划、回调和事务栅栏；超时取消当前事务，只报告已提交前缀。SQLite等待写锁的期限在机械事务内暂设5毫秒，避免驱动的长busy等待拖住取消；事务提交/回滚后、连接归池前恢复该连接原值。锁竞争记录budget_exhausted，其他数据库错误不被吞掉。最终队列成功结账也使用短等待，失败交原worker恢复；普通队列claim、heartbeat及失败结账不计入tick的2秒预算。线程清理和事件循环调度仍有小量开销，不以它承诺生产端到端延迟。

失败按 5、30、120、600 秒退避，第5次隔离；未知 schema 立即隔离。同一可信业务链后续事件阻塞，独立链继续。无法确定归属的异常保守阻塞同 owner/consumer，并显式标记 ordering_key_unavailable；必须经审计修复，不能猜新链绕过。日志与回执不保存异常中的原文、凭证或私有提示词。

业务安装采用进程内的显式注册：先在 EventRegistry 注册已审查消费者，再注册 ConsumerBinding 的可信来源顺序解析器。WakeupBinding 只接受项目代码中的本地回调。HTTP 或模型参数不能提供回调脚本。当前业务消费者接线仍随收件箱方向实施，未安装者健康状态为 not_installed，不宣称已交付。

功能关闭阻止对应新动作，历史读取与已接受任务的机械结账继续。回退时停止该进程的领取、保留历史表；有事件/收据/游标数据时迁移拒绝破坏性降级。不要删除历史或重置游标来消除告警。

本轮验收仅使用临时 SQLite、两个本地 session、假时钟/假队列、进程内服务及配置解析；不包含真实 E2E、provider/模型/行情/账户/通知调用或生产部署验证。持续运行延迟及实际部署恢复时间仍未验证。

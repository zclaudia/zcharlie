## 3. 关键发现

**P1（缺口结论，下一工作包的输入）页面级内嵌体验当前不可达**
后端半边（4edda31）经真机链路全部验证成立（G1/G3/G4），但 App 侧没有打开 web UI 的入口：
无自定义协议注册、`proxyUrl` 仅用于 JSON API、CSP 只允许 `ipc:`；且 HTML 内绝对资源路径
（`/app/static/...`）在网关代理前缀下不可解析（G2 实证 404）。要落地「WebView 里的研究台」，
需要：App 注册自定义协议/导航入口（经 App 传输代理到网关，这也正是 `agent.js` 内嵌轮询所服务的
传输形态）+ 资源路径策略（HTML 相对化或协议内重写）。

**P3-a（沿用 10-15，仍开放）任务卡在 user/assistant 消息上重复渲染**——本轮 13 截图再次可见两份任务卡。

**P3-b（新）「＋」预建会话后发消息不回填标题**——`AgentScreen.tsx` 仅在「无 current 会话直接发消息」
分支用首条消息前 80 字设置标题（`sendMessage` 内的自动建会话分支）；经 `createConversation` 预建后
title 恒为 null，UI 永远显示「未命名对话」。

**观察（UX，按实现即为预期）**：存在会话时，根页面 BACK 的行为是「打开会话列表」，永远轮不到
`Window.close()` 分支——返回键无法退出 app（E1 实测三连 BACK 只在列表开/关间循环）。
`history.length===1`（10-15 报告怀疑的历史残留不成立），是优先级链设计使然。

## 4. 环境事实与流程教训

1. **模拟器连跑 4 天后宿主 NAT 失效**：10.0.2.2 全端口 TCP 不通（ping 亦断），冷启动
   （`adb emu kill` + `-no-snapshot`）恢复。诊断时 toybox `nc` 的退出码不可信（恢复前后均 rc=1，
   而浏览器实际能打开页面）——**前置检查建议改为「模拟器浏览器打开 `http://10.0.2.2:3400/health`」**。
2. **ifind-proxy :7100 本轮未运行**：涉及行情的任务按设计以 `evidence_blocked` `partial` 优雅收束
   （B3 与 task2 均如此），任务状态机与轮询契约不受影响。
3. **dev 库拷贝不带 agent 四键**：P1.3 第③步必须从 `.env` 补写 `investor_agent_enabled` /
   `agent_base_url` / `agent_model` / `agent_api_key` / `agent_max_tokens`；`GET /settings` 的结构是
   `groups[].items[]`（key/value/configured），不是平面 dict。
4. **网关自身健康端点是 `/health`**（`/healthz` 是经代理转发到后端的路径，计划文档笔误一处）。
5. **harness 截图落点**：`M2E_SHOTS` 不随 shell 持久，逐命令调用时极易散落默认目录
   `/tmp/mobile-e2e-shots`（本轮 C/E/F 五张截图事后从该目录抢救归档）。建议后续给 harness 加
   `M2E_SHOTS` 缺省时的显式提醒输出。
6. `am kill` 对前台进程无效；进程回收用例必须 `am force-stop`。
7. WebView 内非 secure context（http 源）没有 `crypto.randomUUID`，脚本化 POST 需自带 UUID。

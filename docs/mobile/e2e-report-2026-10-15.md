## 发现

1. **【P3·疑似缺陷】同一任务的任务卡片重复渲染。** 服务端把同一 `task_ref` 同时挂在
   user 与 assistant 两条消息上（`agent_message.payload.task_ref`），前端对每条带
   `task_ref` 的消息各渲染一张卡：本次 5 个任务渲染了 9 张卡（4 个有回复的任务 ×2 + 1 个取消 ×1）。
   建议前端按 task id 去重（或后端只在 user 消息挂 ref）。功能无损，纯视觉重复。
2. **【计划偏差·已固化进计划】uiautomator 看不到 WebView 子节点**（计划坑 12 应验，TalkBack
   方案因 touch-exploration 干弃用）。改用 Debug 构建自带的 WebView CDP 端口读 DOM/定位
   （Appium WebView 同款机制），动作仍走真实注入（`input tap` / `input text`；中文用 CDP
   `insertText`）。harness 落库为 `tools/mobile-e2e.sh` + `tools/mobile-e2e/cdp.mjs`。
3. **【计划疏漏·已修正】`gateway-admin.sh` 不带 `GATEWAY_URL` 时默认打 3200 常驻网关。**
   本轮因此吃到一次无害的 401（只读 list）。所有签发命令必须显式
   `GATEWAY_URL=http://127.0.0.1:3400`。
4. **【计划疏漏·已修正】隔离后端必须同时起 worker。** 只起 API 时任务永远停在「排队中」
   （B3 首跑卡 4 分钟即此因）。`ia worker start` 与 API 同库同 env 成套启动。
5. **【环境事实】AVD `hermes_api34` 已被既有模拟器实例占用**（另一项目 `dev.sugaring.mobile`
   在前台），新实例 FATAL 退出。采用共存方案：force-stop 其前台 app 后复用实例；zcharlie 侧
   确定性由 `pm clear` 保证（计划原定 `-no-snapshot` 冷启动不适用）。
6. **【观察】硬断网（wifi+data 全关）时连接胶囊翻转慢**：socket 挂起直至 30s 请求超时；
   而杀网关（RST）时秒级翻转。两者都是「连接中断」，但感知延迟差异明显，可在探活上加更短
   的 connect timeout（现有 REQUEST_TIMEOUT_MS=30s）改善。
7. **【观察】int 越界值被客户端 HTML5 校验拦截后 UI 无自定义提示**（浏览器气泡，自动化与
   截图均不可见），与字符串类字段「服务端 422 回显 inline-status」的体验不一致。
8. **【观察】配对页按 BACK 未退出 app**（进程与 Activity 均在）。代码路径为
   `window.history.back()`/`getCurrentWindow().close()`；本轮 WebView 历史疑似有残留条目
   消费了事件。真机空历史下的行为待确认，暂不定缺陷。
9. **【环境事实】`adb shell am start -W` 可能挂住不返回**（F2 首跑卡死一次）。harness 的
   `app_start` 用「轮询进程+CDP 就绪，超时重试」规避。
10. **【操作风险自愈案例】** 执行中 `gateway_namespace` 被一次误操作改写（测试数据本身合法
    导致意外保存成功），经 API 还原后 6 秒内后端重连成功——也顺带验证了「namespace 变更
    热生效」链路。

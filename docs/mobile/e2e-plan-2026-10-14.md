> **2026-10-15 修订**：按 2026-10-15 凌晨首轮自动化执行的结果修订（执行报告见

## 1. 范围

**In scope（本计划覆盖）**

- Debug APK 的干净构建、typecheck、传输层单测（vitest）。
- 模拟器安装、首启、配对、会话/消息/任务、设置页读写、断连恢复、返回键与进程回收。
- 临时网关（zclaudia-gateway Protocol v4）+ 隔离后端实例组成的服务端栈。
- 服务端状态断言（`GET /settings`、`/settings/history`、`/agent/conversations`、`/gateway/status`）。

**Out of scope（本轮不做，注明原因）**

- Release 构建的 HTTPS-only 校验：需要签名密钥与 HTTPS 网关，另行安排。
- 推送通知（`plugin-notification` 已引入但当前 UI 未使用）。
- 真机、多机型分辨率矩阵：本机仅 `hermes_api34`（Pixel 系、API 34、arm64）一台 AVD。
- 后端研究管线的深度正确性：已由 Python 全量套件覆盖，此处只验证手机链路能驱动它。

## 6. 阶段 P1：临时服务栈

约定：`E2E=/tmp/zcharlie-e2e-<timestamp>`，下文以 `$E2E` 指代。所有令牌/凭证只存在于
`$E2E` 与终端历史，不进仓库、不进截图。

### P1.1 临时网关

```bash
mkdir -p "$E2E/gw" "$E2E/shots" "$E2E/logs"
export GATEWAY_ADMIN_TOKEN="$(openssl rand -hex 24)"
cd /Users/zhvala/SourceCode/zclaudia-gateway
GATEWAY_PORT=3400 \
ZCLAUDIA_DATA_DIR="$E2E/gw" \
GATEWAY_ADMIN_TOKEN="$GATEWAY_ADMIN_TOKEN" \
nohup node dist/index.js > "$E2E/logs/gateway.log" 2>&1 &
echo $! > "$E2E/gw.pid"

curl -fsS http://127.0.0.1:3400/healthz     # 预期 200
```

- 健康信号：`/healthz` 200；`gateway.log` 无 error。
- 与常驻网关（3200）完全隔离：独立端口、独立数据目录、独立 admin token。

### P1.2 隔离后端

```bash
cd /Users/zhvala/SourceCode/zcharlie
mkdir -p "$E2E/be"
cp .dev/data/app.db "$E2E/be/app.db"

# （可选）清空拷贝库中的会话数据，获得干净的会话列表：
sqlite3 "$E2E/be/app.db" "
  DELETE FROM agent_task_event; DELETE FROM agent_task_attempt; DELETE FROM agent_task;
  DELETE FROM agent_message; DELETE FROM agent_conversation;"

source .env   # 提供 API_KEY、SETTINGS_ENCRYPTION_KEY、LLM 端点等（同 dev.sh 的做法）
export DATA_DIR="$E2E/be"
export DATABASE_URL="sqlite+aiosqlite:///$E2E/be/app.db"
export APP_ENV=dev
export IFIND_PROXY_URL="${IFIND_PROXY_URL:-http://127.0.0.1:7100}"

.venv/bin/ia migrate up      # 拷贝库对齐当前 schema
# ③ 起隔离后端 :8012（无 --reload）+ research worker（同库同 env，成套启动）
nohup .venv/bin/ia api serve --host 127.0.0.1 --port 8012 > "$E2E/logs/backend.log" 2>&1 &
echo $! > "$E2E/be.pid"
nohup .venv/bin/ia worker start > "$E2E/logs/worker.log" 2>&1 &
echo $! > "$E2E/worker.pid"
sleep 6
curl -fsS -H "X-API-Key: $API_KEY" http://127.0.0.1:8012/healthz    # 预期 200
grep -q research.worker.started "$E2E/logs/worker.log" && echo "worker up"
```

- **不用 dev.sh 的 8002 实例**：它带 `--reload`，并行开发保存文件会整进程重启、网关链路反复重建，
  会把配置问题伪装成产品 bug（2026-10-12 两轮的共同教训）。
- **worker 必须起**（2026-10-15 首轮教训）：agent 任务由 worker 从队列拾取，只起 API 时
  任务永远停在「排队中」，手机端表现为任务卡无进展。
- `SETTINGS_ENCRYPTION_KEY` 必须与生成拷贝时一致（agent_api_key 等密文列才能解开），直接 source `.env` 即可。

### P1.3 服务端预置设置（X-API-Key 直调，替代手工 UI 操作）

JSON API 接受 `X-API-Key` 头（`src/investment_agent/api/auth.py`），比走设置页快且可脚本化。
（设置页 UI 的写入路径本身由 §8 C 组用例单独覆盖。）

```bash
API=http://127.0.0.1:8012
H="-H X-API-Key:$API_KEY -H Content-Type:application/json"
# gateway-admin.sh 必须显式指向临时网关；缺省 GATEWAY_URL 会默认打到 3200 常驻网关！
export GATEWAY_ADMIN_TOKEN="$(cat "$E2E/gw-admin-token")"
export GATEWAY_URL=http://127.0.0.1:3400
GA=/Users/zhvala/SourceCode/zclaudia-gateway/scripts/gateway-admin.sh

# ① 签发后端凭证。注意：输出是多行摘要，token 在最后一行（show once）；
#    [inherit-backend-id] 可把新凭证绑到既有后端身份，避免留孤儿身份。
BACKEND_CRED=$(bash $GA issue-backend zcharlie-e2e e2e-backend)
ZGB=$(echo "$BACKEND_CRED" | tail -n1 | tr -d ' ')    # zgb_ 开头
echo "$ZGB" > "$E2E/zgb.txt"    # 只打印一次并立刻存文件，权限 600

# ② 写入 gateway 五键，让后端连上网关
curl -sS -X PATCH $H "$API/settings" -d "$(cat <<JSON
{"values": {
  "gateway_enabled": true,
  "gateway_url": "http://127.0.0.1:3400",
  "gateway_credential": $(python3 -c 'import json,sys;print(json.dumps(open(sys.argv[1]).read().strip()))' "$E2E/zgb.txt"),
  "gateway_namespace": "zcharlie-e2e",
  "gateway_instance_id": "e2e-backend"
}, "note": "E2E 临时配置"}
JSON
)"

# ③ 写入 agent 对话的运行时门槛（缺一即失败，见 §12）
curl -sS -X PATCH $H "$API/settings" -d "$(cat <<JSON
{"values": {
  "investor_agent_enabled": true,
  "agent_base_url": "<取自拷贝库的 LLM 端点，如 tier3 base_url>",
  "agent_model": "<拷贝库的模型名>",
  "agent_api_key": "<拷贝库解密后的 tier3 key>",
  "agent_max_tokens": 4096
}, "note": "E2E agent 门槛"}
JSON
)"

# ④ 等待后端成功注册到网关，再取「服务 ID」（backend_id = UUID）
sleep 5
curl -sS $H "$API/gateway/status" | python3 -m json.tool   # state=connected 才算就绪
#   注意：backend_id 必须在 PATCH 生效并连上临时网关之后读取；
#   PATCH 前读到的是指向常驻网关的旧注册 id，签 zgd_ 时会报 Unknown backends。
```

## 7. 阶段 P2：自动化基座（harness）

**已落库**：`tools/mobile-e2e.sh` + `tools/mobile-e2e/cdp.mjs`（2026-10-15 首轮实现并实战验证）。

方案：**定位与断言走 CDP，动作走真实注入**。Debug 构建的 WebView 自带远程调试端口
（`webview_devtools_remote_<pid>`，`adb forward tcp:9222` 后即可用）；uiautomator dump 在本镜像
上看不到 WebView 子节点（坑 12），故读 DOM/取坐标/等待断言全部经 CDP（Runtime.evaluate），
点击与键盘仍是系统级注入（`input tap` / `input text`），中文输入用 CDP `Input.insertText`。
与 Appium 的 WebView automation 同机制。

harness 命令面：`tap / taplast / type_ascii / insert_text / text / lasttext / eval /
waittext / waitlast / waitgone / waitsel / jsclicklast / shot / key / swipe /
app-stop|start|restart|clear`。关键实现约定：

1. **坐标换算**：CSS rect × `devicePixelRatio`（2.625）+ WebView 容器屏幕原点
   （uiautomator dump 里 `android.webkit.WebView` 节点的 bounds 左上角，键盘弹起会变、每次重取）。
2. **先清空再输入**：`input text` 从光标处插入不清空，重复填同一字段会拼接——type 前先经 CDP
   置空并派发 input 事件（React 状态同步）。
3. **末元素选择器**：`querySelector` 永远返回第一个匹配；对话页多张任务卡时必须用
   `lasttext/taplast` 定位最后一张（活动中的那张）。
4. **点击验证重试**：消息列表随任务事件自动 `scrollIntoView`，从取 rect 到落地 tap 的间隙里
   元素会位移导致点击落空（首轮 B4/C4 各踩一次）——点击后必须断言效果（按钮文案变化/请求发出），
   不生效则换坐标无关的 `el.click()`（`jsclicklast`）兜底。
5. **就绪轮询**：`app_start` 轮询「进程存活 + CDP 可读」而非盲等；`am start -W` 在某些状态下
   会挂住不返回，不能作为唯一就绪信号。
6. 断言双写：UI 断言（CDP 文本）+ 服务端断言（`X-API-Key` curl / sqlite 只读），两者都过才算过。

  `设备凭证格式无效，应以 zgd_ 开头。`。

**A2 坏凭证被拒（negative）**

## 12. 已知坑与风险（历史踩坑 → 预案）

| # | 坑 | 预案 |
| --- | --- | --- |
| 1 | `env.sh` 把 ANDROID_HOME 回退到 `~/Library/Android/sdk`（本机不存在） | 所有构建命令显式 export 三件套（§5） |
| 2 | 常驻网关在 3200 | 临时网关固定用 3400，teardown 复核 3200 健康 |
| 3 | dev API `--reload` + 并行开发 = 假故障 | 一律用隔离后端（P1.2），无 reload、独立端口 |
| 4 | macOS 本地网络隐私（TCC）静默拒后端出网 LLM 调用 | 若 B3 卡「研究中」且后端日志无 LLM 响应：重启后端进程即恢复；仍失败再查 ifind-proxy |
| 5 | agent 四键缺一：缺 `investor_agent_enabled` 每条消息 409 `execution_denied`；缺 `agent_max_tokens` 报 `finite_output_token_bound_required` | P1.3 第③步一次写齐，B3 前先 curl 确认生效 |
| 6 | 服务 ID 误填 `gateway_instance_id`（字符串）而非 `backend_id`（UUID）→ AUTH_FAILED | P1.3 明确从 `/gateway/status` 取；A2 故意制造一次 AUTH_FAILED 作对照 |
| 7 | SDK 对非 `zgb_` 凭证走 peer_hello 直连，网关报通用 UNAUTHORIZED，UI 只显示 AUTH_FAILED | 真因看 `gateway.log` / `backend.log`；凭证一律来自 gateway-admin.sh 签发 |
| 8 | `input text` 空格/特殊字符 | `%s` + 逐字符转义规则（§7） |
| 9 | 软键盘改变布局导致坐标失效 | 每次输入后 BACK 收键盘再 dump |
| 10 | 模拟器快照残留状态 | `-no-snapshot` 冷启动；用例间用 pm clear 控制 |
| 11 | Debug 才允许明文 HTTP | 全程 Debug APK；Release + HTTPS 另立计划 |
| 12 | uiautomator 对 WebView 节点偶发只返回容器 | harness 规则 5 的无障碍复位；仍不行则退化为「截图人工判读」并记录 |
| 13 | 后端鉴权节流（错 key 按 IP 限流） | 断言脚本只用正确 `$API_KEY` |
| 14 | `gateway-admin.sh` 缺省 GATEWAY_URL 默认 3200 常驻网关 | 所有调用显式 `GATEWAY_URL=http://127.0.0.1:3400`（2026-10-15 首轮吃到一次无害 401） |
| 15 | `issue-backend/issue-device` 输出是多行摘要，token 只在最后一行 | `… \| tail -n1 \| tr -d ' '` 提取；重复签发用 `issue-backend <ns> <name> <backend-id>` 继承身份避免孤儿 |
| 16 | `backend_id` 在 PATCH 生效前读是指向常驻网关的旧注册 | 一律在 `/gateway/status` 显示 `state=connected` 且 ns 正确之后再读 |
| 17 | 隔离栈漏起 worker → 任务永远「排队中」 | P1.2 成套起 worker，健康信号 `research.worker.started` |
| 18 | 消息列表自动滚动导致坐标 tap 落空 | 点击后断言效果，不生效换 `jsclicklast` 兜底（harness 内建） |
| 19 | `adb shell am start -W` 可能挂住 | `app_start` 轮询进程+CDP 就绪，超时重试 |
| 20 | 测试用「看似合法」的值会真的保存（如合法标识符的 namespace） | 破坏性字段测试选**确定非法**的值（空串/非法字符）；误存后立即经 API 还原并等待 `state=connected` |
